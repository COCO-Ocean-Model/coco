## 1. はじめに

COCO ver.6.0.0 は以下のような特徴を持つ海洋大循環モデル(OGCM)である。
- Primitive equations に基づく定式化
- 陽解法による free surface の表現
- 時間方向の差分として staggered time-stepping を選択可能
- 鉛直 z-sigma ハイブリッド座標系(海面からある一定深度まで sigma)
- 水平一般曲線直交座標系
- 極座標等の二極座標系に加えて三極座標系 (tripolar grid) を使用可能
- Partial step による海底地形表現
- 海底境界層モデルの導入
- 海氷 ice thickness distribution スキーム

---
COCO ver.6.0.0 は COCO ver.5.0 の開発コードのうち、海洋生態系モデル部分を取り除いたものをオープンソースソフトウェア化したものである。COCO ver.5.0 からの主なアップデートは、
- 海洋単独コードの廃止およびオフラインモデルの統合
- staggered time-stepping の標準化と leap-frog + Euler backward + Euler forward スキームの廃止
- 海面境界条件 JRA55-do 利用コードの追加
- 新しい混合スキームの導入
- NetCDF による入出力の導入

などである。

COCO ver.5.0 は COCO ver.4.9 をベースに作成された。このバージョンでは全ての実行コードが書き換えられた。
具体的変更点は、
- F95 化による自由形式への書き換え
- `module` の全面的導入とそれに伴う `include` 文の排除 (文関数関係を除く)
- `common` 文の削除
- 非 MPI 並列コードの廃止
- build プロセスの変更

などである。これらの変更は元になった COCO4.9 での計算結果とのバイナリ一致を取りながら行ったので、
バージョン変更により計算結果は変化しない
(はずであるが、あらゆる計算設定でテストしているわけではないので、バグを埋め込んでいたらご指摘ください)。

Ver.4.9 では、以下が導入された
- 時間発展のスキーム staggered time-stepping
- 三極座標系 tripolar grid system

モデルコンパイル時のオプションにより、水平一般曲線直交座標系 (極 2 つ) は引き続き利用可能である。
このうち水平座標系については、モデルのソースコード自体は水平方向に一般の曲線直交座標系上で定式化されているが、
具体的な水平座標系の生成方法、および三極座標系における座標系の選び方についてこのパッケージで対応している方法には制限がある。詳しくは「2.2 [地形の設定とマスキングファイルの作成](#setup-mask)」の説明を参照のこと。

Ver.4.3 では海氷モデルは従来の 2-category 0-layer から multi-category (ice thickness distribution) 1-layer へと変更された。

Ver.4.2 では海氷モデルのパッケージを同時に含み、モデルコンパイル時の選択により海洋単独モデルか海氷－海洋モデルのいずれかを選べるようになった。

---
パッケージには MPI を用いた分散メモリ型並列化コードが含まれている。
ノード間通信を伴う並列化によって計算速度がどの程度上昇するかは、一般に通信性能および分割領域の大きさと通信量の比に依存する。
また、ノード内でベクトル化または並列化が行なわれる場合には、分割された領域におけるループ長をあまり小さくするのは得策でない。
実際、水平格子数が小さい場合には、ノード間並列化によって計算速度はかえって低下する。
並列化モデルの使用にあたっては、並列化されたモデルを用いるだけの価値が本当にあるのかに関して、予備実験等を通して十分に検討をすることをすすめる。
また、これに関連して、「9. [並列化モデルの状況に応じたチューニング](#parallel-tuning)」にも必ず目を通しておいていただきたい。

COCO は Unix 環境でコンパイル・実行することのみを念頭においている。
パッケージ管理者の開発環境から、Linux 上で
- Intel Fortran compiler
- GNU Fortran compiler
- Fujitsu Development Studio (Wisteria-O, Fugaku など)
- NEC SDK (ES4 など)

を用いる場合に標準的に対応している。
他の Unix 環境への移植も Makefile が include しているシステム依存部分の記述ファイルを用意するだけで容易に行なうことができる (と思います)。

本プログラムは基本的に Fortran95 で書かれている。

COCO は以前は、AORI 海洋モデリンググループ構成員、
および AORI 海洋モデリンググループと共同研究を行なう者に対してのみ公開・配布されていた。
2026 年 9 月以降は、著作権者やライセンスなどを整えた上で、
COCO をオープンソースソフトウェア化し、GitHub 上で公開した。

モデルの名称は CCSR Ocean Component Model で、略称を COCO とする。便宜上、
海氷が結合されたものを IcedCOCO とも呼ぶが、正式名称には Iced をつけない。
また、2010 年度に海洋研究所との統合により CCSR という組織名がなくなって以降は、
COCO は何の略称でもなく単に海洋大循環モデルの名称とされている。

## 2. ソースの展開と実行手順

ソースコードのパッケージを展開すると以下のサブディレクトリが作成される

- `RUN/`     : 実行スクリプトサンプル
- `bin/`     : 実行形式ファイルの置き場
- `bound/`   : 簡単な海面境界条件ファイル作成プログラム
- `init/`    : 簡単な初期条件ファイル作成プログラム
- `lib/`     : プログラムライブラリの置き場
- `mask/`    : マスキングファイル作成ユーティリティ
- `src/`     : ソースコード
- `extra/`   : 付属ツール

このうち `extra/` 以下はモデルの構築・実行等に直接関係しないが、座標変換などの具体例を示したコード群である。
詳しくは、同ディレクトリ内の `README_convert` を参照のこと。

<a id="setup-os"></a>

### 2.1 OS の設定

ディレクトリ `src/` に存在する `Mkinclude` というファイルの中の
`SYSTEM` という変数の設定を行なう。標準的に用意されているものは
```makefile
SYSTEM = ES4v # NEC SX-Aurora (ES4 の VEノード) を用いる
SYSTEM = ifort # Intel Fortran を用いる
SYSTEM = gfortran # GNU Fortran を用いる
SYSTEM = fugaku # 東大 Wisteria, Fugaku などで Fujitsu Fortran を用いる
```
である (実際にはさらにいくつかの設定が入っていますが)。
これ以外の OS の場合にはその OS に対応するシステム依存部分を記述したファイルを用意することから始めなければならない。

続いて、同じく `src/Mkinclude` において、
`OPTTRIPOLE` という変数を設定することで二極座標系 (極座標系など)・三極座標系のいずれを用いるかを選択する。
選択方法は 
```makefile
OPTTRIPOLE =               # 二極座標系 (bipolar grid system)
OPTTRIPOLE = -DOPT_TRIPOLE # 三極座標系 (tripolar grid system)
```
である。
ver.4.9.3.2 以降では、`src/Mkinclude` において、
`OPTEXMASK` という変数を設定することで次に作成するマスキングファイルに含まれる情報を拡張することが可能となっている。
選択方法は
```makefile
OPTEXMASK =              # 旧仕様のマスキングファイルを作成/使用する
OPTEXMASK = -DOPT_EXMASK # 拡張マスキングファイルを作成/使用する
```
である。
現在、拡張マスキングファイルは一部の非標準スキームを利用する際に必須の設定だが、
それらを使わない場合にこのオプションを指定しても実行に支障はない。
ただし、このオプションを指定して構築した実行ファイルで、
以前のバージョンを含め旧仕様で作成されたマスキングファイルを読み込むことはできない。

<a id="setup-mask"></a>

### 2.2 地形の設定とマスキングファイルの作成

COCO ver.4 は COCO ver.3.4 をベースに作成され、大きな違いは水平座標系が球面座標系
(座標系の回転を含む) に限定されなくなったことである。
ただし、モデルのソースコード自体は水平方向に一般の曲線直交座標系上で定式化されているが、
具体的な水平座標系の生成方法としては地理座標系を polar stereographic projection で平面上に射影し、
それを複素平面上で linear fractional transformation を用いて変換し、
それを球面上に戻すという方法による方法のみをこのパッケージでは与えている。
それ以外の水平座標系を用いたい場合には、
マスキングファイル生成プログラムを変更するなどして必要な情報 (計量など) を作成する必要がある。

ディレクトリ `mask/` には

- `GEO`         : 地形ファイル
- `Makefile`    :
- `Sysdep.*`    : Makefile における機種依存部分
- `xmkmsk.F`    : マスキングファイル作成プログラム

というファイルが存在する。

まずは `GEO` というファイルを編集することから始める。
このファイルではグリッド数や座標系等のパラメータを指定し、続いて地形の情報を書き込む。
このうちパラメータ設定部分は、用いる座標系が二極座標系か三極座標系かで書式が異なる。

#### パラメータ設定部分：二極座標系 (bipolar grid system) の場合
`GEO` ファイルには先頭から順に各行に

- `NX`: 東西方向のグリッド数
- `NY`: 南北方向のグリッド数
- `NZ`: 鉛直方向のグリッド数
- `KZ`: 鉛直グリッドのうち sigma 座標で扱うものの数
- `NIC`: 海氷モデルの厚さカテゴリ数。海洋単独モデルの場合には 0 とする
- `INODES JNODES`: 東西方向の領域分割数、南北方向の領域分割数
- `ALONW ALONE`: 領域の西端および東端の経度 (度)
- `ALATS ALATN`: 領域の南端および北端の緯度 (度)
- `IMERC`: 緯度方向のグリッド生成方法
  - `IMERC = 0` : 緯度で等分割
  - `IMERC = 1` : Mercator projection された第二次元で等分割
  - `IMERC = 2` : 陽にグリッド幅を与える
- `DLAT`: `IMERC = 2` の場合のみ指定する。緯度方向グリッド幅の `NY` 個の並び (度)
- `DZ`: 鉛直方向のグリッド幅の `NZ` 個の並び (m)
- `HIC`: 海氷厚さカテゴリの `NIC` 個の並び (cm)
- `PLON PLAT`: モデル座標系の北極点の地理座標系上での経度・緯度 (度)
- `QLON QLAT`: モデル座標系の南極点の地理座標系上での経度・緯度 (度)
- `ITHIRD`: 水平座標系生成の一次変換に必要な第 3 の点の指定方法。
  - `ITHIRD = 0`: モデル座標系の経度 180, 緯度 0 が、上記で指定した二つの極の中点に存在する。したがって、第 3 点の変換を陽に指定する必要はない。
  - `ITHIRD = 1`: 次の行の指定により第 3 点の変換を陽に指定する。
- `ELON ELAT`: `ITHIRD=1` の場合のみに指定する。地理座標系上でのこの経度・緯度に、モデル座標系の経度 `PLON`, 緯度 0 の点が存在する。

という量が並ぶ。ここで、経度・緯度および東西南北という表現を用いたが、
「地理座標系上」という断りがない限りこれは地理的なものを指すのではなく、
用いる一般曲線直交水平座標系における座標および方向を指す。
すなわち、水平座標系の第一次元および第二次元 (それぞれ地理座標系を考える場合には地理的な経度・緯度)
の座標値はそれぞれ最大で 0 から 360 (-180 から 180 などでも別に構わないが) および -90 から 90 の範囲の値をとり、
それぞれ後述する一次変換によって地理座標系上の経度・緯度に対応する。
その対応に鑑みての経度・緯度および東西南北という表現である。
また、経度方向を x 方向、緯度方向を y 方向という語で指す場合もある。

経度方向のグリッド幅は等間隔に限定されており、`NX`, `ALONW`, `ALONE` から自動的に決定される。
一方、緯度方向のグリッド幅は陽に指定することができ (`IMERC = 2`)、
緯度によってグリッド幅が変化することが許されているが、
緯度値として等間隔あるいは Mercator 座標系で等間隔にとりたい場合にはそれぞれ
`IMERC = 0, 1` とすることで、陽にグリッド幅を指定しなくてもよい。
`IMERC = 1` を選択した場合、当然のことながら `ALATS = -90` および `ALATN = 90` とすることは許されない。

水平座標系の選択に関して、このモデルパッケージでは、
1. 地理座標系の経度線・緯度線を polar stereographic projection で複素平面上に射影する
2. 射影された座標線を一次変換で複素平面上で写像する
3. 複素平面上で写像された座標線を polar stereographic projection の逆により球面上に射影する

という方法による水平座標系の生成方法のみを用意している。
一次変換の等角写像としての性質から、生成される水平座標系は直交座標系であることが保証される。

一次変換は 3 点の変換によって一意に決定されるため、
その 3 点を `(PLON, PLAT)`, `(QLON, QLAT)`, `(ELON, ELAT)` で指定する。
うち 2 点は地理座標系の特異点である北極点と南極点の移動先であり、
これらを陸上ないし領域外の任意の場所を指定して移動させる。
もう 1 点の変換元と変換先については、特別なこだわりがないのであれば、`ITHIRD = 0` として自動的に決定させることができる。
この場合、モデル座標系の経度 180 度、緯度 0 度が地理座標上で `(PLON, PLAT)` と `(QLON, QLAT)` を通る大円の中点にくるように変換される。
ただし、この方法は `QLON = PLON + 180` かつ `QLAT = - PLAT` である場合には用いることができない。
球面座標系の回転のみを考慮する場合はこれに当てはまる。
この場合、および任意に第 3 点の変換を選びたい場合には `ITHIRD = 1` とし、
モデル座標系の経度 `PLON`, 緯度 0 度の地理座標上での座標値 `(ELON, ELAT)` を指定する。
第 3 点としてモデル座標系の `(PLON, 0)` を選ぶようにしたのは、回転変換を考える場合の便宜である。
回転変換の場合には、`PLAT > 0` ならば `ELON = PLON, ELAT = PLAT - 90` とし、
`PLON < 0` ならば `ELON = PLON + 180` (もしくは `PLON - 180`), `ELAT = - PLAT - 90` とすればよい。
また、通常の地理座標系を用いる場合には、
`PLON = 0, PLAT = 90, QLON = 0, QLAT = -90, ITHIRD = 1, ELON = 180, ELAT = 0` とする。

より一般の水平座標系を用いたい場合、上記と同様に polar stereographic projection
を用いて複素平面上での座標変換を考えるが変換を一次変換に限定せずにより一般の等角写像とする場合であれば、
`xmkmsk.F` の変更は容易である。
その場合、その函数および導函数によってプログラム中の `CONF`, `DCONF` を定義し直せば、計量については同じ手続きで求められる。
それ以外の場合には計量の求め方まで含めてプログラムを作り変えなければならない。
いずれにせよ、このマスキングファイル作成において計量が適切に求められてさえいれば、
OGCM 本体を変更することなく一般の曲線直交座標系を用いることができる。

`INODES`, `JNODES` は東西方向・南北方向の分割数で、
現在のところ分割された各領域は必ず同じ大きさ(各次元とも)でなければならない。
したがって、`INODES`, `JNODES` はそれぞれ `NX`, `NY` の約数でなければならない。
また、`INODES = NX` または `JNODES = NY`とするとモデルは正常に動作しない
(普通はそんなことをしようとは思わないでしょうけど...)。
`KZ` は 1 以上の値を指定し、海面から第 `KZ` 層までに対して sigma 座標の定式化が適用される。

#### パラメータ設定部分：三極座標系 (tripolar grid system) の場合
`GEO` ファイルには先頭から順に各行に

- `NX`: 東西方向のグリッド数
- `NY1 NY2`: 地理座標系部分 (`NY1`) および一般曲線直交水平座標系部分 (`NY2`) における南北方向のグリッド数
- `NZ`: 鉛直方向のグリッド数
- `KZ`: 鉛直グリッドのうち sigma 座標で扱うものの数
- `NIC`: 海氷モデルの厚さカテゴリ数。海洋単独モデルの場合には 0 とする。
- `INODES JNODES`: 東西方向の領域分割数、南北方向の領域分割数
- `ALATS`: 領域の南端の緯度 (度)
- `DLAT`: 緯度方向グリッド幅の `NY1+NY2` 個の並び、南端のグリッドから北向きに並べる (度)
- `DZ`: 鉛直方向のグリッド幅の `NZ` 個の並び、上端のグリッドから下向きに並べる (m)
- `HIC`: 海氷厚さカテゴリの `NIC` 個の並び (cm)
- `PLON PLAT`: 一般曲線直交水平座標系部分の北極点の地理座標系上での経度・緯度 (度)

という量が並ぶ。

三極座標系を用いる場合、このパッケージでは
1. 座標系全体は、地理座標系部分と一般曲線直交水平座標系部分から成る。
2. 一般曲線直交水平座標系としては、地理座標上のある緯度 `PLAT` を指定して、
極をその緯度上で経度方向に互いに 180 度離した `(PLON, PLAT)`, `(PLON+180, PLAT)` に配置した、
座標値の範囲 (90W, 90E), (90S, 90N)、グリッド数 `(2xNY2) x (NX/2)` の座標系を用意する。
3. 地理座標系としては、座標値の範囲が `(PLON, PLON+360)`, `(ALATS, PLAT)`
でグリッド数が `NX x NY1` の座標系を用意する。
4. このようにして用意された 2 つの座標系を、地理座標系の東西方向 (同緯度線上)
のあるグリッド境界と一般曲線直交水平座標系の極間を結ぶ方向 (地理的な緯度に当たる方向)
のあるグリッド境界を一致させるように結合する。
これを、モデルで用いる座標系とする。

という方法での座標系生成のみに対応している。
この場合、地理座標系部分の北限は必ず 90N よりも南であり、
したがって極は地理座標系部分に 1 つ (南極)、
一般曲線直交水平座標系部分に 2 つ (地理座標上の `(PLON,PLAT)` と `(PLON+180,PLAT)` の 2 点) の計 3 つ存在する。
この座標系を三極座標系 (tripolar grid system) という。
なお、付属している [`README_tripolar_GEO.png`](README_tripolar_GEO.png) に以上の説明が図示してある。

本項の説明で、経度・緯度および東西南北という表現は、
「地理座標系上」および「一般曲線直交水平座標系上」という断りがない限り、
用いる三極座標系の水平第一次元および第二次元を示す。
この際、三極座標系上の東西・南北は地理座標系上の東西・南北と一致した方向をそれぞれ意味するものとする。

このパッケージの三極座標系における経度方向の幅は 360 度、座標値は `PLON` から `PLON+360` に固定されている。
すなわち、地理座標系部分では三極座標系の西端および東端が `PLON` の経線と一致する。
経度方向のグリッド幅は等間隔に限定されており、自動的に `360/NX` 度となる。

三極座標系の緯度方向については、南端は -90 から `PLAT` の範囲で指定し、その値を `ALATS` に記述する。
北端は `PLAT+90` 固定である。`ALATS` から `PLAT` までが地理座標系部分、
`PLAT` から `PLAT+90` までが一般曲線直交水平座標系部分に相当する。
緯度方向のグリッド幅は `DLAT` 部分において陽に指定する。
この際、緯度によってグリッド幅が変化してもよい。
ただし上述の設定から、`DLAT` の最初の `NY1` 個の値の合計は `PLAT-ALATS`、
後ろの `NY2` 個の値の合計は 90 に等しくなければならない。
なお、`DLAT` の設定の際には、三極座標系の緯度は地理座標系部分では地理座標上の緯度と (当然だが) 一致するが、
一般曲線直交水平座標系部分では地理座標上の `90-PLAT` 度が三極座標系上の 90 度に相当することに注意が必要である。

[例] `PLAT = 63.0` で、63N 以南の地理座標系部分の南北グリッド幅を 1 度に設定したとする。
一般曲線直交水平座標系部分では、地理座標の `90.0-63.0=27.0` 度分が三極座標系の 90 度分に相当するから、
63N 以南と南北幅を一致させるならば、南北グリッド幅は `1.0*(90.0/(90.0-63.0))= 3.3333...` 度としなければならない。
 
その他のパラメータの指定法は二極座標系と同様である。
ただし、三極座標系においては `JNODES` は `NY1+NY2` の約数でなければならない。
この際、`JNODES` が `NY1` と `NY2` の公約数である必要はない
(つまり、同一の計算ノード上に地理座標系部分と一般曲線直交水平座標系部分が共存していても問題ない)。

#### 接合部の不連続の緩和について
三極座標系では、地理座標系と一般曲線直交水平座標系の接合部でグリッド情報の不整合が生じる。
このような場合においても、熱、トレーサー等は保存するようにコーディングがなされているが、
運動量に関してはその限りではない。
また、グリッドの幅は本来、緯度および経度の幅 `(DY, DX)` とメトリック `(Hy, Hx)` の積で計算されねばならないが、
一部のコードにおいて、近似的にメトリックを用いず緯度、経度幅をグリッド幅とし代用している。
この場合、メトリックの不連続が存在するグリッドの接合部で著しい不整合が生じる場合がある。
この問題を緩和するため、`FACTY` を導入し、緯度幅と対応するメトリックに重みをつけ、
緯度幅をグリッド幅とした際の不連続を緩和する。
`FACTY` は一般曲線直交水平座標の赤道に沿ったメトリックと地理座標系の緯度方向のメトリックの比と定義する。

#### 地形設定部分
続いて地形を書き込む。これは数値の NX 個の並びを NY 行続けたものであり、一番上が北端、一番下が南端となるように書く。
座標系変換を行なう場合には、変換後の座標系のおける地形を書き込む。
値は

- 0     : 陸
- 正の数: 海洋の深さ (鉛直グリッド数)

を表す。
たとえば 12 という数字が書かれていれば、そのグリッドは第 12 層目までの深さを持つ海洋であるとみなされる。
鉛直グリッド数に小数部分を持つ数を指定すると partial step (Adcroft et al., 1997) を用いることになる。
たとえば 12.4 という数字が書かれていれば、そのグリッドは第 13 層目までが海洋として扱われ、
第 13 層目の上から `0.4*DZ(13)` の深さに海底が存在するものとして扱われる。
もちろん、正の数として指定してよいのは `NZ` までの値に限られる。
また、海洋のグリッドのうち sigma 座標が適用される範囲には海底が存在してはならない。
すなわち、海洋の深さを指定する正の数としては `KZ` 以上の値を与えなければならない。

地形情報は FORTRAN で
```fortran
REAL*8 AGEO(NX, NY)

DO J = NY, 1, -1
   READ(IGFILE, *) (AGEO(I, J), I = 1, NX)
END DO
```
という形で読まれるので、
これで読むことができるようなテキスト形式であればどのような書式で書いても構わない
(もちろん整数を並べてもよく、ver.3.1 までの `GEO` ファイルもそのまま利用できる)。
ただし、読み込まれた実数値の小数第 4 桁が四捨五入して扱われる。
これを変更したい場合には `xmkmsk.F` を書き換える必要がある
(`NROUND` がデフォルトでは 1000 になっているが、第 $n$ 桁で四捨五入する場合にはこれを $10^{n-1}$ にすればよい)。
なお、小数部分を 0 でない小さい値にとると数値不安定を生じやすくなることを注意しておく。

`GEO` ファイルがここまでで終っている場合には海底境界層モデルが使用されないものとしてマスキングファイルが作成される。
海底境界層モデルを使用する場合には上記の地形情報に続いて

`IBBL`: 海底境界層モデルを用いるかどうかの指定

を書く。
この `IBBL` の値が 0 の場合には海底境界層モデルは用いないものとしてマスキングファイルが作成され、
`GEO` ファイルのこれ以降の部分は無視される。
`IBBL` に 0 以外の値を指定すると海底境界層モデルを用いるためのマスキングファイルが作成される。
この場合、`IBBL` を指定した行に続いて、先ほどの地形情報と同様の書式によって海底境界層モデルを適用するグリッドを指定する。
ここで指定した値が 0 であるグリッドに対しては海底境界層が存在せず、正の数を指定したグリッドに対しては海底境界層が存在するとみなされる。
例えば先ほどの地形情報と全く同じものをここに書いておくと、海洋である全グリッドに対して海底境界層が存在するものとして扱われる。
なお、海底境界層モデルと partial step を同時に用いることにも支障はない。

海底境界層モデルを用いる場合、地形情報に指定される数値は `NZ-1` まででなければならない。
モデルにおいては地形情報で指定した海洋最下層グリッドの直下および第 `NZ` 層に海底境界層の変数が保持される。
現在のモデルにおいては海底境界層の厚さは一定として扱われ、その厚さは `DZ(NZ)` で指定される。

モデルにおいては、領域の東西端は常に周期的につながっているものとして扱われている。
すなわち、領域の東端(西端)のグリッドの東隣(西隣)には西端(東端)のグリッドが存在するものとして扱われる。
したがって、例えば東西に周期的につながっていない矩形の領域を用意したい場合には、
南北方向に 1 列以上の陸地を設定する
(東西方向の場所はどこでも構わないが、東西どちらかの端にするほうが便利であろう)。
南北端については、二極座標系の場合は周期的に取り扱われておらず、
最北端グリッドの北側および最南端のグリッドの南側には境界(陸地)があるものとして取り扱われる。
三極座標系の場合、南端は周期的に取り扱われておらず、
一方領域の北端は西半分と東半分が互いに結合しているとみなされる。

あとは
```bash
make
```
によって `xmkmsk.F` がコンパイルされ、実行される。実行の結果

- `MASK`      : マスキングファイル
- `zocdim.F90`: 次元ファイル

という二つのファイルが作られる。`zocdim.F90` において `NTDIM` の値を設定する。
これはトレーサーの次元であり、最低値は 2 で、その場合にはトレーサーとして温度・塩分のみを扱うことになる。
その他のトレーサーに関する計算を行ないたい場合には必要な数だけ `NTDIM` の値を大きくする。
温度・塩分のみを扱う場合には、`zocdim.F90` を編集する必要はない。
その後 `zocdim.F90` を `src/module/` にコピーする。

マスキングファイルにはグリッド幅・計量・マスキング配列が含まれている。マスキング配列の主たるものは

- `AMSKT`: T 点の海陸マスク
- `AMFTX`: T 点変数の x 方向フラックスに対するマスク
- `AMFTY`: T 点変数の y 方向フラックスに対するマスク
- `AMFTZ`: T 点変数の鉛直方向フラックスに対するマスク
- `AMSKV`: V 点の海陸マスク
- `AMFVX`: V 点変数の x 方向フラックスに対するマスク
- `AMFVY`: V 点変数の y 方向フラックスに対するマスク
- `AMFVZ`: V 点変数の鉛直方向フラックスに対するマスク

であり、基本的には計算に有効な点に対しては 1 が、そうでない点に対しては 0 が与えられている。
ただし、`AMFTX`, `AMFTY` は鉛直グリッド幅
(これらが定義される面を挟むふたつのグリッドボックスの T 点鉛直グリッド幅のうち小さい方。
sigma 座標の領域では海面高度を 0 とした場合の有次元のグリッド幅)
が乗じられており、`AMFVX`, `AMFVY` については z 座標の領域についてのみ鉛直グリッド幅
(これらが定義される面を挟むふたつのグリッドボックスの V 点鉛直グリッド幅のうち小さい方)
が乗じられている。

#### オプションスキームによるリスタートデータ

オプションスキームが独自の予報変数を持つ場合、リスタート時にはそれらの予報変数の初期条件も必要とされる。
どのような変数が必要になるかはオプションスキーム (の組合せ) に依存する。
上記デフォルトの変数については、最上位プログラムで定義されるため、リスタートファイルの読み書きは一括して行なわれる。
オプションスキームで新たに必要となる変数はオプションプログラムにおいてローカルに定義されることになるため、
それら変数については、リスタートファイルの読み書きは各オプションプログラムにおいて行なわれる。

オプションスキームが必要とする予報変数の読み書きのため、
変数の予報を行なうプログラム (オプションプログラムに限らない) の形式には一定のルールが設けられている。
以下にそのルールを示す。具体的な例については `option/dvdif.nk.F90` などを参照のこと。
- 各プログラムはリスタートファイルの読み込みをコントロール変数 `OINIT` (LOGICAL)
と書き出しをコントロールする変数 `OFINAL` (LOGICAL) を参照する (`zocdim.F90` で定義されている)
- 各プログラムの実行部分の最初は `IF (OINIT) THEN` で始まる IF ブロックであり、
リスタートファイルから読み込むローカル変数が存在しない場合には単に `RETURN` のみ、
存在する場合には `CALL RSTADD(...)` によってそれを指定した後に `RETURN` とする。
- `IF (OFINAL) THEN` で始まる IF ブロックがそれに続き、
リスタートファイルへ書き出すローカル変数が存在しない場合には単に `RETURN` のみ、
存在する場合には `CALL FINADD(...)` によってそれを指定した後に `RETURN` とする。

リスタートファイルへの書き出しは、まずデフォルト変数を一括して書き出し、
続いて `OFINAL = .TRUE.` として `INISET`, `PREDCI`, `PREDCO` が順に呼ばれる。
`PREDCI`, `PREDCO` では具体的なモデル計算のサブルーチンが順に呼ばれる。
`IF (OFINAL) THEN` のブロック中に変数書き出しが指定されている場合には、リスタートファイルにその変数が追加される。

リスタートファイルが読み込まれる場合には、やはり `OINIT = .TRUE.` として
`INISET`, `PREDCI`, `PREDCO` の順に処理されていくため、
`IF (OINIT) THEN` のブロック中に対応する変数読み込みが指定されていれば、
書き出されたのと同じ順が保証された上でそれらが読み込まれる。

なお、リスタートファイルがデフォルトの変数以外しか含まない場合でも、実行は可能である。
その場合、`RSTADD` を呼んだ結果として引数 `OEOF` に `.TRUE.` が返されるので、
各オプションプログラム内でゼロセットするなどの処理を行なうことを前提とする。
必要なオプション変数の一部だけがリスタートファイルに存在するという場合には、現状では対応していない。

と設定しておき、`ranlib` コマンドが必要でなく、したがって `ranlib` が存在しない場合には、

```makefile
RANLIB = touch
```
などという無害なコマンドを指定しておくとよい。

モデルの選択は、変数 `MODEL` の指定で行なう。
海氷-海洋モデルならば
```makefile
MODEL = icedcoco
```
とし、オフラインモデルならば
```makefile
MODEL = offline
```
する。

座標系の指定は、マスキングファイルの作成の際に既に述べたとおり
`OPTTRIPOLE` で行う。二極座標系の場合何も指定しない、すなわち
```makefile
OPTTRIPOLE = 
```
三極座標系の場合は
```makefile
OPTTRIPOLE = -DOPT_TRIPOLE
```
とそれぞれ指定されていることを確認する。

body forcing を用いるかどうかの選択は、変数 `OPTBDY` の指定で行なう。
用いない場合にはこの変数に何も指定しない。すなわち 
```makefile
OPTBDY =
```
とする。用いる場合には
```makefile
OPTBDY = -DOPT_BODY
```
と指定する。

icedcoco で海面塩分緩和を行なえるようにしたい場合には
```makefile
OPTSRST = -DOPT_SRST
```
と指定する。
なお、これを指定した場合でも、実際に海面塩分緩和を行なうかどうかは、実行時のパラメータファイルで指定する (後述)。
この指定を行なった場合には、必ず海面塩分の境界条件ファイルを用意せねばならない。
指定しなかった場合には、境界条件ファイルは必要ない。

海底境界層モデルを用いない場合には変数 `OPTBBL` に何も指定せず、用いる場合
には
```makefile
OPTBBL = -DOPT_BBL
```
と指定する。

拡張マスキングファイル使用の有無は、作成の際に既に述べたとおり `OPTEXMASK` で行う。
実行時に旧仕様のマスキングファイルを読み込む場合は何も指定せず、拡張マスキングファイルを読み込む場合は
```makefile
OPTEXMASK = -DOPT_EXMASK
```
と指定されていることを確認する。
なお、このオプションを指定した場合、旧仕様のマスキングファイルを読み込ませようとすると実行時エラーとなる。
逆にオプションを指定しない場合、拡張マスキングファイルを読み込ませても正常に動作する。

ファイルの入出力に MPI-I/O を用いる場合は
```makefile
OPTIO = -DOPT_IO_COCOMPI -DOPT_IO_BYTESWAP -DOPT_IO_SEQUENTIAL
MPI=.mpi
```
と指定する。
ここで、`-DOPT_IO_BYTESWAP` は big endian のファイルを使用する際に指定し、
未指定では little endian のファイルとして入出力が行われる。
`-DOPT_IO_SEQUENTIAL` は sequential access のファイルとして入出力が行われ、未指定では stream access となる。

運動量の移流スキームは標準ではエネルギー保存のみを考慮したものであり、
また、斜面を上る・下る斜め方向の移流は考慮されていない。
これに対し、疑似エンストロフィー保存および斜面方向運動量移流を考慮したスキームも用意されている。
この選択は変数 `SRCENS` の指定で行なう。標準のスキームを使う場合には
```makefile
SRCENS =
```
と何も指定せず、疑似エンストロフィー保存・斜面方向運動量移流スキームを用いる場合には
```makefile
SRCENS = aocea aprdc binst bstbc cadvc ctnuv dvlva
```
と指定する。
本来は `option/` ディレクトリに置いて `SRCOPT` で指定すべきところだが、変更箇所が多いのでこのような形にした。
このスキームを用いることによって、当然のことながら計算量は増加する。
中規模渦を解像しないような場合にはこのスキームを用いる利点は存在しないと思われるので、
意味もなく使用しないように注意すること。

非標準ルーチン使用の設定は、オプションとして取り込みたいルーチンについて、
そのオブジェクトファイルの名前を変数 `SRCOPT` に与える。
用意されている非標準ルーチンとその使用方法については「7. [非標準スキームについて](#option-scheme)」で述べる。
なお、非標準ルーチンの中には事実上の標準スキームも含まれているので、
通常の使用の場合にも非標準ルーチンの説明に目を通すことをおすすめする。

あとは
```bash
make
```
を実行することにより、ソースを展開したディレクトリの `lib` 以下にプログラムライブラリが、
`bin` 以下に実行形式が作成される。
ライブラリ、実行形式の名前は `Mkinclude` の `LIBOGCM`, `TARGET` という変数でそれぞれ指定される。
デフォルトの実行形式名は、海氷－海洋モデルが `icedcoco`、オフラインモデルが `offline` である。

なお、ディレクトリ `src/` には `depend.icedcoco/` `depend.offline` `enstr/`
`module/` `option/` `shared/` `build/` というサブディレクトリが存在し、それぞれ

- `depend.icedcoco`: 海氷－海洋モデルのみが必要とするプログラム
- `depend.offline` : オフラインモデルのみが必要とするプログラム
- `shared`         : 共通標準プログラム
- `enstr`          : エンストロフィー保存の非標準プログラム
- `module`         : module ファイル
- `option`         : `SRCOPT` に指定する非標準プログラム
- `build`          : 実際にコンパイルに使用したプログラムのリンク

が置かれている。
また、`src/` の直下にはメインプログラムである `icedcoco.F90`, `offline.F90` が存在する。

### 2.7 実行パラメータ

積分時間・タイムステップ・出力およびモデルパラメータは NAMELIST によって実行時に指定する。
指定するのは以下の要素である (NAMELIST での値の与え方の例とともに示す)。

#### メッセージ出力
```fortran
&NMSTDO CSTDO='STDOUT' &END
```
- `CSTDO`: 実行中のメッセージの出力先ファイル名

実行時のメッセージは各ノードごとに別々のファイルに書き出される。ファイル名は `CSTDO` に、拡張子としてランク数が付加されたものである。

#### 実験名
```fortran
&NMRUN CRUN='OGCM TEST RUN' &END
```
- `CRUN`: 実験名 (メッセージの始めに書き出されるだけ)

#### 積分時間 (詳しくは「3. [時刻管理について](#time-manage)」を参照のこと)
```fortran
&NMTIME ITSTRT=0,1,1,0,0,0, ITEND=1000,1,1,0,0,0,
        TMSTP=24, IUTSTP=4, NTSPLT=40 &END
&NMCALN ICALN=0 &END
&NMRSTR IRINTV=1, IURINT=1, IRSRWD=1 &END
```
- `ITSTRT`: 積分開始時刻 (年・月・日・時・分・秒)
- `ITEND` : 積分終了時刻 (年・月・日・時・分・秒) 
- `TMSTP` : タイムステップ
- `IUTSTP`: `TMSTP` の単位 (1:年, 2:月, 3:日, 4:時, 5:分, 6:秒)。
これが指定された場合、`TMSTP` は整数化して扱われる。
これが指定されなかった場合、単位は「時」とみなされ、`TMSTP` は小数部分まで意味を持つ。
- `NTSPLT`: 海面高度予報におけるタイムスプリット回数。海面高度の予報は `TMSTP/NTSPLT` のタイムステップで行なわれることになる。
- ICALN : カレンダーの種類
  - 0: 1 カ月 = 30 日、1 年 = 360 日
  - 1: 1 年 = 365 日 (閏年でない通常年を繰り返す)
  - 2: 1 年 = 365 or 366 日 (グレゴリオ暦に基づく閏年を含む)
- `IRINTV`: リスタートファイルの出力間隔
- `IURINT`: `IRINTV` の単位 (1:年, 2:月, 3:日, 4:時, 5:分, 6:秒)
- `IRSRWD`: リスタートファイルを上書きするか否か
  - 0: 上書きしない
  - 1: 上書きする

#### 初期条件・リスタートファイル
```fortran
&NMFINI CFINIT='INITIAL', IRSTRT=0 &END
&NMFRST CFREST='RESTART' &END
```
- `CFINIT`: 初期条件ファイル名
- `IRSTRT`: 初期条件ファイルに書かれた時刻の情報を無視するかどうか
  - 0: 無視する
  - 1: 積分開始時刻と一致していない場合には実行しない
- `CFREST`: リスタートファイル名

#### マスキングファイル
```fortran
&NMMASK CFMASK='MASK' &END
```
`CFMASK`: マスキングファイル名

#### 結果出力 (詳しくは「6. [結果の出力について](#output)」を参照のこと)
```fortran
&NMDOUT IODSTR=999,1,1,0,0,0, IODEND=1000,1,1,0,0,0,
        IODINT=1, IUDINT=2, IODAVR=1, IODSNG=1 &END
```
- `IODSTR`: デフォルトの出力開始時刻 (年・月・日・時・分・秒)
- `IODEND`: デフォルトの出力終了時刻 (年・月・日・時・分・秒)
- `IODINT`: デフォルトの出力間隔
- `IUDINT`: デフォルトの `IODINT` の単位 (1:年, 2:月, 3:日, 4:時, 5:分, 6:秒)
- `IODAVR`: デフォルトの時間平均出力選択
  - 0: 各出力間隔の最後の時刻における瞬間値を出力する
  - 1: 各出力間隔についての時間平均値を出力する
- `IODSNG`: デフォルトの出力データ精度
  - 0: 倍精度実数 (`REAL(8)`)で出力する
  - 1: 単精度実数 (`REAL(4)`) で出力する

```fortran
&NMHIST COHITM='T', COHFIL='t',
        IOHSTR=999,10,1,0,0,0, IOHEND=999,11,1,0,0,0,
        IOHINT=1, IUHINT=3, IOHAVR=0, IOHSNG=0,
        IOXSTR=51, IOXEND=150, IOYSTR=101, IOYEND=200, IOZSTR=3, IOZEND=5
&END
```
- `COHITM`: 出力する変数のアイテム名。複数の変数を出力する場合には、それぞれに対して `&NMHIST` で始まる行を用意する。
以下の指定はこの値で指定された変数に対してのみ有効。
- `COHFIL`: 出力ファイル名。指定されないとエラーとなって実行終了。
- `IOHSTR`: 出力開始時刻。デフォルトは `IODSTR`
- `IOHEND`: 出力終了時刻。デフォルトは `IODEND`
- `IOHINT`: 出力間隔。デフォルトは `IODINT`
- `IUHINT`: `IOHINT` の単位 (1:年, 2:月, 3:日, 4:時, 5:分, 6:秒)。デフォルトは `IUDINT`
- `IOHAVR`: 時間平均出力選択。デフォルトは `IODAVR`
- `IOHSNG`: 出力データ精度。デフォルトは `IODSNG`
- `IOXSTR`: 出力範囲の経度方向始点。デフォルトは 1
- `IOXEND`: 出力範囲の経度方向終点。デフォルトは `NX`
- `IOYSTR`: 出力範囲の緯度方向始点。デフォルトは 1
- `IOYEND`: 出力範囲の緯度方向終点。デフォルトは `NY`
- `IOZSTR`: 出力範囲の鉛直方向始点。デフォルトは 1
- `IOZEND`: 出力範囲の鉛直方向終点。デフォルトは 1 (2 次元変数) または `NZ` (3 次元変数)

#### 結果出力 (密度座標)
  (詳しくは「6.6 [密度座標での結果出力について](#output-density)」を参照のこと)
```fortran
&NMSGCO CFSGCO='SCOORD' &END
```
- `CFSGCO`: 出力用の密度座標系の定義ファイル名。有効なファイル名が与えられると、密度座標で結果を出力できるようになる。

`NAMELIST NMDOUT` に以下のパラメータを追加：
```fortran
&NMDOUT IODSVI=0 &END
```
- `IODSVI`: デフォルトの密度座標出力方法選択
  - 0: 出力の際、各密度層の層厚を変数に乗じない
  - 1: 出力の際、各密度層の層厚を変数に乗じる

`NAMELIST NMHIST` に以下のパラメータを追加：
```fortran
&NMHIST COHVCO='sigma2_l106', IOSVIN=0 &end
```
- `COHVCO`: 出力する密度座標系の識別名。デフォルト (指定しない場合) は、z座標系で出力する。
- `IOSVIN`: 密度座標で出力する際、変数の値に各密度層の層厚を乗じるか。
デフォルトは `IODSVI`。密度座標出力でない場合、無視される。

#### 海面境界条件 (詳しくは「4. [境界条件ファイルについて](#bound-file)」を参照のこと)

```fortran
&NMSFBC CFTAUX='TAUX', CFTAUY='TAUY', CFTSFC='TSFC', CFQSFC='QSFC',
        CFSWNT='SWNT', CFDWLW='DWLW', CFWFLX='WFLX', CFPSFC='PSFC',
        CFUSFC='USFC', CFSSFC='SSFC' &END
&NMNPER ONMPER=F &END
```
- `CFTAUX`, `CFTAUY`, `CFTSFC`, `CFQSFC`, `CFSWNT`, `CFDWLW`, `CFWFLX`, `CFPSFC`, `CFUSFC`, `CFSSFC`:
順に、風応力東西成分、風応力南北成分、海上気温、海上比湿、海面短波放射、海面長波放射、海面水フラックス、海面気圧、海上風速、海面塩分のファイル名。
それぞれについて詳しくは後述。
- `ONMPER`: `.TRUE.` の場合、降水(降雪)・蒸発・河川流入による海面(海氷上面)での淡水の出入りが、全球平均で0になるように降水または蒸発を調整する。
海洋から淡水が抜ける量が多い場合は降水を全球一様に増やし、海洋に淡水が入る量が多い場合は蒸発を全球一様に増やす。
これらの操作によって潜熱フラックス等は直接影響を受けない。
上記修正量(cm/s)は、以下を指定してヒストリデータとして出力できる。
```fortran
&NMHIST COHITM='FWNML', COHFIL='fwnml' &END
```

#### Body forcing (必要な場合のみ)
```fortran
&NMBODY CFTBDY='TBDY','SBDY', CFTDMB='TDMB','SDMB' &END
&NMSKIB IYSKIB=1,1,1,1,1,1 &END
```
- `CFTBDY`: トレーサー値のファイル名。それぞれのトレーサーに対して対応するファイル名を並べて指定する。
1 番目が温度、2 番目が塩分である。デフォルトのプログラムでは body forcing は温度・塩分に対してのみ与えられる。
それ以上の個数のトレーサーを定義してそれらに対しても body forcing を与えたい場合には
`sfcng.F90` および `utint.F90` の対応する部分を surface forcing にならって書き換える
(これらのファイル中、書き換えるべき箇所はすでに用意されており、コメントアウトされている)。
- `CFTDMB`: トレーサー値の緩和における時定数のファイル名。それぞれのトレーサーに対して対応するファイル名を並べて指定する。
1 番目が温度、2 番目が塩分である。デフォルトのプログラムでは…(以下同文)
- `IYSKIB`: 境界条件ファイルを先頭から読み直す時に加算される年(温度、塩分、温度緩和時定数、塩分緩和時定数の順)。
なお、`IYSKIB` の行が存在しなければ、全てに対して 1 が与えられる。

#### 海底地熱
```fortran
&NMGTHM OGTHM = T, CFGTHM = 'GTHM' &END
```
- `OGTHM`: 海底地熱を与えるかどうか。陽に指定しなければ FALSE となり、海底地熱は適用されない。
- `CFGTHM`: 海底地熱フラックスのファイル名。単位は mW/m^2 (= erg/s/cm^2)。

#### 物理パラメータ
```fortran
&NMVISH AMH=5.D+9 &END
&NMDIFH AHH=1.D+7 &END
&NMDFSH ASH=1.D+6 &END
&NMVISV AMV0=5.D0,4.D0,3.D0,2.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0 &END
&NMDIFV AHV0=1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0 &END
&NMBTMF BTMFRC=1.3D-3 &END
```
- `AMH`: 水平渦粘性係数 (cm^2/s)
- `AHH`: 水平渦拡散係数 (cm^2/s)
- `ASH`: 海面高度に対する水平拡散係数 (cm^2/s)。
数値計算における不安定を解消するためのパラメータ。`AHH` より十分小さい値であることが望ましい。
- `AMV`: 鉛直渦粘性係数 (cm^2/s)。各層に対する値の `NZ` 個の並び
- `AHV`: 鉛直渦拡散係数 (cm^2/s)。各層に対する値の `NZ` 個の並び
- `BTMFRC`: 海底摩擦係数 (無次元)

水平渦粘性係数を tapering off のために東西グリッド幅に比例して変化させる場合には、
```fortran
&NMCVIS IAM=0, AMH=5.D+6 &END
```
水平粘性係数の空間分布をファイルで与える場合には、
```fortran
&NMCVIS IAM=1, CFAMH='AMH' &END
```
を指定する。
- `IAM`: デフォルトは -1 (`AMH` 一様)、グリッド幅に比例させる場合 0、
水平粘性係数をファイルから読む場合 1 を指定する。
- `CFAMH`: 水平粘性係数を与えるデータのファイル名。
ファイルは海面境界条件と同形式だが、時間変動には対応していない (ヘッダとデータ 1 組のみが有効)。

上記で指定した水平渦粘性は外部モード速度にも同様に適用される (同じ NAMELIST を参照する)。
外部モードはタイムスプリットのために解かれる回数が多く、その中で粘性計算は最も負荷が高い。
外部モード速度に対する粘性は数値安定性のために入れてあるのだが、問題が生じないならば本来適用の必要はない。
外部モード速度に対する粘性を適用しない場合は、
```fortran
&NMNOVIS LNOVIS=T &END
```
を指定する。

パーシャルステップを用いる場合に斜面の海底付近の鉛直流に不自然な不連続が生じることがある。
これは、パーシャルステップにおける水平粘性・側面摩擦の取り扱いが厳密でないことに起因する。
これを厳密に表現するスキームを適用する場合は、
```fortran
&NMPSLV OPSLVIS=T &END
```
を指定する。

#### 海底境界層の物理パラメータ
```fortran
&NMBBVH AMHBBL=5.D+9 &END
&NMBBDH AHHBBL=1.D+7 &END
&NMBBDV AMVBBL=5.D0, AHVBBL=5.D0 &END
&NMBBRF RAYFRC=1.D0, MZN=15, MZS=15 &END
```
- `AMHBBL`: 水平渦粘性係数 (cm^2/s)
- `AHHBBL`: 水平渦拡散係数 (cm^2/s)
- `AMVBBL`: 鉛直渦粘性係数 (cm^2/s)。
実際に適用される鉛直渦粘性係数はこの値と `AMV(NZ)` のうち大きい方である。
Turbulent closure scheme や diffusive adjustment を用いた場合にはそれが最小値として適用される。
- `AHVBBL`: 鉛直渦拡散係数 (cm^2/s)。実際に適用される値に関しては鉛直渦粘性係数と同様。
- `RAYFRC`: Rayleigh 摩擦の factor (無次元)。
海底境界層に対する Rayleigh 摩擦の係数はその場の Coriolis paramter の絶対値に RAYFRC をかけた値が適用される。
- `MZN`, `MZS`: Rayleigh 摩擦を適用する層の下限。北半球 (`MZN`) および南半球 (`MZS`) において、
ここで指定した層の深さまでに存在する海底境界層に対してのみ Rayleigh 摩擦が適用される。
default の値は `MZN`, `MZS` ともに `NZ`。なお、摩擦係数・下限層とも、必ずしもこのデフォルトの設定方法を推奨しているわけではない。
実際には Rayleigh 摩擦を適用する深さの下限により複雑な地域依存性を考慮する方がよいかもしれないが、
それを標準的に与えることができるようなパッケージは整備されていない。

#### 数値計算の技術上のパラメータ
```fortran
&NMWUPC ALPHA=8.0D-1, ALPHAV=9.7D-1 &END
&NMACCV ACC=3.D+2 &END
&NMACCB ACCB=1.D+2 &END
&NMACCT GAMMA=1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0,1.D0 &END
&NMIMPL AIMP=5.D-1 &END
```
- `ALPHA`: 水平移流項における重みつき上流差分の重み
- `ALPHAV`: 鉛直移流項における重みつき上流差分の重み
- `ACC`: Bryan (1984) の加速法における加速係数 (baroclinic mode 運動方程式)
- `ACCB`: Bryan (1984) の加速法における加速係数 (barotropic mode 運動方程式)。陽に指定しなければ `ACC` と同じ値が仮定される
- `GAMMA`: Bryan (1984) の加速法における加速係数 (温度・塩分の式)。各層に対する値の `NZ` 個の並び
- `AIMP`: semi-implicit 法の係数

#### 海氷－海洋モデルに特有のパラメータ
```fortran
&NMLWEM EMIS=0.97.D0, OLWNET=T &END
&NMSAIR ZA=2.D0 &END
```
- `EMIS`: 海面の長波射出率 (デフォルト値: 1)
- `OLWNET`: 海面下向き長波データの代わりに正味長波をあたえるかどうか (デフォルト値: `.FALSE.`; 正味でなく下向き分のみで与える)
- `ZA`: 海上気温・比湿の定義高度 (デフォルト値: 2m)

```fortran
&NMSRST OSRSTR=T, OSRSTI=F, SDMP=20 &END
```
- `OSRSTR`: 海面塩分への restoring を行なうかどうか (デフォルト値: `.FALSE.`; 行なわない)
- `OSRSTF`: 海氷存在下で海面塩分への restoring を行なうかどうか (デフォルト値: `.FALSE.`; 行なわない)
- `SDMP`: restoring の時定数 (単位 day, デフォルト値: 0)。
前述した通り、塩分緩和を行うには `src/Mkinculde` において `OPTSRST` の指定も忘れず行うこと。

```fortran
&NMAMIN AMIN=1.D-6, AMAX=1.D0 &EDN
```
- `AMIN`: 海氷存在率の最小値。これよりも小さな存在率を持つ厚さカテゴリの海氷は存在しないものとして扱われる。
この値を 0 に指定してはいけない。
- `AMAX`: 海氷の密接度の最大値。
粗い分解能のモデルでは十分に表現することができない lead 形成の効果を簡単な形でパラメタライズしたものであり、
常に最低 `1-AMAX` の開水面が存在するように、各厚さカテゴリの海氷存在率・厚さが調整される。
負値や 1 を越える値を指定した場合の動作は保証しない (`AMIN` についても)。

```fortran
&NMIDYN ECC=2.D0, DMIN=2.D-7, FLOSS=17.D0, OPT_PICE=F &END
```
- `ECC`, `DMIN`, `FLOSS`: 海氷の力学パラメータ。
- `OPT_PICE`: .`TRUE.` の場合海氷力学的強度の計算を Hibler (1979) の方法で行なう
これは本来2 カテゴリー海氷モデル向けの方法であるが、マルチカテゴリーモデルに用いても数値的な問題はない。
パラメータとして以下を指定する。

```fortran
&NMPICE P0=5.D5 &END
```
- `P0`: Hibler (1979) の `P*` パラメータ (単位 dyn/cm)
```fortran
&NMIPRM THETAA=0.D0, THETAO=25.D0, CWDRAG=5.D-3, ELAST0=0.25D0, KGLEV=1 &END
```
- `THETAA`: AGCM で求められた海面風応力に対し、それが海(氷)面に対して作用するときの回転角 (degree)。
本来「風応力」は既に海上風からの回転角が考慮されているものを指すのであるが、
オフラインで使用する場合の便宜などを鑑みて、回転角を指定できるようにしておいた。
北半球ではその絶対値、南半球ではその絶対値を負にしたものが適用される。デフォルトは 0 度。
- `THETAO`: 海氷－海洋間応力における回転角 (degree)。
北半球ではその絶対値、南半球ではその絶対値を負にしたものが適用される。デフォルトは 25 度。
- `KGLEV`: 上記回転角 `THETAO` は海氷と海洋の相対速度に対して適用されるが、そのとき用いる海洋流速の深さレベル。
デフォルトは 1 であるが、このデフォルト値はまず間違いなく誤った選択で、
正しくはエクマン層下端 (地衡流が実現される深さ) という、定義のあいまいな場所にとるべきもの。
指定したレベルが海底より下にあれば、海洋の流速として 0 が適用される。
- `CWDRAG`: 海氷－海洋間の drag coefficient。
- `ELAST0`: Hunke and Dukowicz (1997) の elastic-viscous-plastic sea ice rheology における elasticity に関するパラメータ。

```fortran
&NMITSP NSPLIT=60 &END
```
- `NSPLIT`: 海氷の力学部分の time splitting における、繰り返し回数。
目安としては、100 km 程度の水平格子間隔に対して time step が数分になるように選ぶ。
デフォルト値は 60 であるが、通常は 10 程度でよいはず。

```fortran
&NMISLT SI=3.D0 &END
```
- `SI`: 海氷に含まれる平均的な塩分。

```fortran
&NMBTAB FBTAB=0.5D0 &END
```
- `FBTAB`: 開水面が暖められる場合に、その熱のうち海氷の下面融解に使われる割合。残りは側面融解に使われる。

#### 潮汐流のパラメータ

月太陽惑星の位置から起潮力ポテンシャルを計算し、外部モード運動方程式の
外力として適用することで潮汐流を表現するには以下を指定する。
```fortran
&NMTIDE OTIDE=T &END
```
NASA JPL が作成した太陽系の惑星と月の位置に関するデータセット DE430 を使用する。
データセットはアスキー形式およびバイナリ形式で構成されたデータファイル JPLEPH として用意されている。
バイナリ形式データは direct access で読む前提で作成されており、COCO の標準的 I/O 方式とは異なる。
JPLEPH に対して装置番号を他のファイルと被らないように以下のように陽に指定する。
```fortran
&NMJPLD CPLEPH='JPLEPH', NRFILE=80, NRECL=4 &END
```
- `CPLEPH`: データセット DE430 のファイル名
- `NRFILE`: `CPLEPH` で指定したファイルの装置番号
- `NRECL`: direct access で `RECL` を byte 単位で指定する処理系の場合には 4、word 単位で指定する処理系の場合には 1

DE430 は惑星と月の位置 (と速度) に関する事実上の国際標準データセットであり (国立天文台も暦計算に使用している)、 
1550年12月21日から2650年1月25日までの間について任意の天体間の相対位置と速度を得ることができる。
時間については多項式補間を行う。なお、DE にはいくつものバージョンがあり、
ものによっては紀元前からのデータも含む (例えば DE431 は DE430 の長期間バージョンとして 13201 BC から 17191 AD をカバーする)。
試してはいないが、DE の異なるバージョンでもこのプログラムで読み込み可能である。

DE430 から得られるのは 2000 年分点の平均赤道面および平均春分点に基づく位置であり、各瞬間の視位置は歳差や章動の分だけずれる。
ここでは歳差は修正するが (Lieske et al., 1977, Astron. Astrophys.)、章動や光行差は修正しない。
おそらくそのために、月・太陽の赤経に0.002 度程度の誤差を生じる (歳差を修正しないとその 100 倍ずれる)。

上記の起潮力ポテンシャルに加えて、潮汐流を減衰させる効果も同時に考慮する必要がある。
まず、海底摩擦による潮汐流の減衰を Jayne and St. Laurent (2001) のパラメタリゼーションによって表現する。
関連パラメータは以下の通り。
```fortran
&NMBFJL CFRGHN = 'ROUGHNESS', LSCALE=7.d3, KSFR=17, RGHMAX=1.d30, BVFMAX=1.d30 &END
```
- `CFRGHN`: 粗度 (Jayne and St. Laurent (2001) の (3), (4)式のh^2に相当するもの) 情報のファイル名。
形式は水平2次元倍精度の unformatted, sequential access であるが、GTOOL 形式のようなヘッダは含まれていない。
- `LSCALE`: 長さスケール、単位は m。
- `KSFR`: 指定した層とそれより深い層のみにパラメタリゼーションを適用。
- `RGHMAX`: 粗度の上限値
- `BVFMAX`: 浮力振動数2乗の上限値

デフォルトでは消散が主に潮汐のみに効くように
順圧流速の25時間平均には Jayne and St. Laurent (2001) のパラメタリゼーションが適用されていない (Arbic et al., 2010)。
この平均流速の設定は次のように指定する。
```fortran
&NMBFAV  NBT=25, IOBINT=1, IUBINT=4 &END
```
`IOBINT` (時間間隔), `IUBINT` (時間単位番号) で指定した時間間隔毎に平均値を計算し、その `NBT` 個のセットが保存される。
上の設定では1時間毎にデータセット更新を行う25時間平均を用いてる。

固体地球潮汐の効果の表現は以下のように設定する。
```fortran
&NMTBDY ALPHA=0.7d0 &END
```
- `ALPHA`: 起潮力ポテンシャルに `ALPHA` が乗じられる。通常 `ALPHA = 0.7` 程度。

self-attraction/loading の効果は以下のように設定する。
```fortran
&NMTSAL BETA=0.d0 &END
```
- `BETA`: 海面高度勾配に `(1-BETA)` が乗じられる。

### 2.8 実行

実行のためのスクリプトのサンプルは `RUN/` に `GO.coco.par` という名前で用意されている。このスクリプトについて説明する。

まず `BINARY`, `RUNDIR` の二つの変数をしかるべく設定する:
- `BINARY`  : モデルの実行形式ファイル名
- `RUNDIR`  : モデルの実行を行なうディレクトリ

変数 MPIRUN も指定する:
- `MPIRUN`  : MPI のプログラムを実行するためのコマンド (`mpirun`, `mpiexec` など)

並列ノード数も実行環境に応じて設定する。並列計算に必要なノード数は領域分割の個数 (= `INODES * JNODES`) であり、
それ以上の数を指定する。通常は `INODES * JNODES` を指定するが、それよりも大きな数を指定しても実行に支障はない。

スクリプトには実行時のパラメータ指定の NAMELIST が続くが、それらはいったんファイルに出力される。
そのファイル名を変数 `PARAMET` に指定する:
- `PARAMET`: パラメータファイル出力先。

プログラムにおいてはこの出力されたファイルを OPEN してパラメータを読み込む。
メインプログラムにおいてはそのファイル名が陽に指定されているので、
用意されているスクリプトに書かれている変数値 (`PARAMET`) から変更する場合にはメインプログラムの変更も必要となる。
用意されているスクリプトではパラメータファイルは `$RUNDIR` に作成され、
プログラムではこれに装置番号 7 番 (`zocfil.F90` 中で定数 `NFPARM` で定義) が割り当てられる。

実行の際のメッセージは装置番号 `NFSTDO` に書き出される。
`NFSTDO` は標準では FORTRAN の標準出力番号である 6 になっており、
そこにパラメータファイルで指定される名前のファイルが割り付けられる。
ファイル名はデフォルトでは `STDOUT` になっている。

用意されたスクリプトの NAMELIST 中でファイル名を指定する場合、相対パスで書かれている場合には `$RUNDIR` に対する相対パスとなる
NAMELIST の部分はいったん shell を通してファイルに書き出されてから使われるので、その中の表現に shell の環境変数などを使用することができる。

## 3. 時刻管理について

モデル内部では通算秒 (`TT`) によって時刻を管理している。
一方、ユーザーが陽に扱う時刻は年・月・日・時・分・秒 (`IDATE`) であり、必要に応じてモデル内で `TT` と `IDATE` の変換が行なわれる。
変換を行なうためのツールは `ucaln.F90` に用意されている。

時刻の変換に際しては、まず始めに使用するカレンダーの種類を選択する。
```fortran
CALL CALNDR(ICALN)
INTEGER ICALN ! カレンダーの種類
!ICALN = 1      : 閏年でない通常年を繰り返す
!ICALN = 2      : グレゴリオ暦に基づく閏年を含む
!ICALN = その他 : 1 年を 360 日、1 月を 30 日とする
```
変換は
```fortran
CALL CYH2SS(TT, IDATE) ! 年・月・日・時・分・秒 -> 通算秒
CALL CSS2YH(IDATE, TT) ! 通算秒 -> 年・月・日・時・分・秒

REAL*8  TT       ! 0 年 1 月 1 日 0 時 0 分 0 秒を 0 とする通算秒
INTEGER IDATE(6) ! 年・月・日・時・分・秒の順に要素とする配列
```
で行なう。

なお、`TT` は `REAL(8)` であるので、有効桁数は 15 桁程度である。
これ以上に有効桁を必要とするような使い方のもとでの動作は保証されない。

例: 1,000,000,000 年 1 月 2 日 3 時 4 分 5 秒 を積分開始時刻とし、time step を 15 秒とする (この場合、おそらく時刻が進まない)

## 4. 境界条件ファイルについて

### 海氷－海洋モデル

このパッケージのままモデルを動かす場合、境界条件として
- `TAUX`: 海面風応力東西成分 (Pa, 東向きが正)
- `TAUY`: 海面風応力南北成分 (Pa, 北向きが正)
- `USFC`: 海上風速 (m/s)
- `TSFC`: 海上 2m 気温 (K)
- `QSFC`: 海上 2m 比湿 (nondimensional)
- `DWLW`: 海面における下向き長波放射 (W/m^2, 下向きが正)
- `SWNT`: 海面における正味短波放射 (W/m^2, 正値)
- `WFLX`: 海面淡水フラックス (m/s, 海面から淡水が抜かれる向きが正)
- `PSFC`: 海面気圧 (Pa)

が必要とされる。書式は [4.1](#41-データ形式) に述べる。
ただし、全てのデータは海洋の T-点上で値が定義されているとみなされる。
海面で塩分の緩和を行なう場合には

- `SSFC`: 海面塩分 (psu)

も必要になる。なお、海氷－海洋モデルにおける海面塩分緩和は、第一層の塩分を直接変化させ、海水の量 (体積) には影響を及ぼさない。

海面での駆動力のうち、淡水フラックスと風応力は上記のデータで与えられたものがそのまま課される。
熱フラックスのうち潜熱・顕熱フラックスについては bulk formula を用いて求められる。
その計算は `sfcng.F90` に含まれているサブルーチン群で行なわれており、
そこにある bulk formula は Kara et al. (2000, JAOT) を CCSR/NIES AGCM 5.7 の形式に埋め込んだものである。
Bulk formula として何かを用意しておかなければモデルパッケージとして成立しないので、標準としてこれをつけてあるが、
いつでもこれを使っていれば安心ということは決してないのでご注意を。

CORE や JRA55-do などの海面境界条件データを用いる場合には独自のバルク式を適用する必要があるため、非標準スキームを用いる。
詳細は「7. [非標準スキームについて](#option-scheme)」の「[境界条件](#option-scheme-bound)」を参照のこと。

### 4.1 データ形式
データファイルは FORTRAN の書式なし形式で、
```
ヘッダ1 (時刻1 を含む)
データ1
ヘッダ2 (時刻2 を含む)
データ2
…
ヘッダN (時刻N を含む)
データN
```
という並びになっており、
```fortran
CHARACTER CHEAD(64)*16 !
INTEGER   IDATE(6)     ! データの時刻(年・月・日・時・分・秒)
INTEGER   IUNIT        ! ファイルの装置番号
REAL*8    VALUE(NXY)   ! データの値

READ(IUNIT) CHEAD
READ(IUNIT) VALUE
READ(CHEAD(50), '(I6.6,5I2.2)') IDATE
```
の形で読めるものとする。ヘッダの時刻以外の情報は参照されないので、`CHEAD(50)` 以外には何が書かれていても構わない。

時刻は必ず 時刻1, 時刻2, ..., 時刻N の順に増えていかなければならない。そうでない場合の動作は保証しない。

<a id="bound-file-time-interp"></a>

### 4.2 時刻と内挿について

データ数 (N) が 1 の場合には内挿は行なわれず、始めに 1 回だけデータを読み込んで、その値を使い続ける。この場合時刻は意味を持たない。

データ数 (N) が 2 以上の場合には、ファイルに書かれた時刻とモデル内での現在時刻に基づいて内挿が行なわれる。
このとき、ファイルに書かれた時刻の「年」の値そのものには意味がなく、時刻1 から 時刻N までの年の相対値のみに意味がある。

時刻 I と 時刻 I+1 (I = 1, ..., N) の差がモデルの time step を下回るような場合にも、動作は保証されない。
なお、時刻 N+1 はこの後に説明される方法で決定される。

末尾のデータの次には先頭のデータが続くものとみなされる。
```
ヘッダ1
データ1
ヘッダ2
データ2
…
ヘッダN
データN
--- end of file ---
(ヘッダN+1)
(データN+1)
(…)
```
データ N+1 は データ1 と同じである。時刻 N+1 に関しては

- 時刻 N の月日時分秒が 時刻 1 の月日時分秒よりも後の場合には、
時刻 N の年に IYSKIP (default の値は 1) を加えたものを時刻 N+1 の「年」とみなし、
時刻 N+1 の月日時分秒は時刻 1 の月日時分秒と同じとみなす

- 時刻 N の月日時分秒が 時刻 1 の月日時分秒よりも前の場合には、
時刻 N の年に `IYSKIP - 1` を加えたものを 時刻 N+1 の「年」とみなし、
時刻 N+1 の月日時分秒は時刻 1 の月日時分秒と同じとみなす

ものとして扱われる。`IYSKIP` は実行時に読むパラメータファイルで指定できる。
データ N+I (I = 1, ..., N) はデータ I と同じであり、
時刻 N+I は時刻 N+I の年と時刻 N+1 の年の差が時刻 I の年と時刻 1 の差と同じであるものとして扱われる。
同様にして時刻とデータが無限に続いているものとして取り扱われる。

季節変動する境界条件を各月の代表値で与えるのであれば、N = 12 として、適当な時刻をファイルに書き込んでやればよい。
時刻 1 を 1 月にするのであれば、全ての時刻について「年」は同じものを書き込むことになる。
時刻 1 が 1 月でなければ、1 月から後は「年」がひとつ増えることになる。
先頭に何月が来ようが実行には影響しない。例えばファイルが
```
時刻1=0000000116000000                時刻1=0019970316000000
1 月のデータ                          3 月のデータ
時刻2=0000000216000000                時刻2=0019970416000000
2 月のデータ                          4 月のデータ
…                                    …
時刻12=0000001216000000               時刻12=0019980216000000
12 月のデータ                         2 月のデータ
```
であるふたつの場合について、どちらも同じ結果になることを保証する。

年々変動する境界条件を与える場合でも、必要な数のデータを用意し、適当な時刻をファイルに書き込むだけでよい。
ただし、ファイルを末尾まで読んでしまってさらに積分が続く場合には、ファイルを先頭から読み直すことに注意しなければならない。
10 年分の境界条件を与え、その 10 年を繰り返すような場合であれば、`IYSKIP` を 10 にすればよい。

全ての境界条件ファイルについてデータ数 (N) や時刻が一致している必要はない。
すなわち、風応力は一定のものを与え続け温度・塩分は季節変動させるという場合であれば、
風応力のデータ数を 1 にし、温度・塩分のデータ数を適当な値にするということでよい。

データ数 (N) が 2 以上の場合について、具体的な内挿の行なわれ方やデータの更新のタイミングについては「5. [境界条件の時間内挿について](#bound-time-interp)」を参照のこと。

### 4.3 温度・塩分について body forcing を与える場合

海面での restoring と同様の方法で body forcing を与えるための非標準ルーチンも用意されている。必要なデータは

- 温度 (℃)
- 温度の restoring における係数(time constant の逆数) (1/s)
- 塩分 (psu)
- 塩分の restoring における係数(time constant の逆数) (1/s)

であり、それぞれについてファイルを用意する。データの形式は海面境界条件の場合と同じであり、データ長が NXYZ になる。
すなわち、全領域に対し照する温度・塩分をファイルで用意する。そして restoring を行ないたくないグリッドに対しては係数を 0 にする。

より効率的に body forcing を行ないたい場合には、body forcing に対するリストベクトルを用意し、
restoring の係数が 0 でないようなグリッドにおいてのみ計算を行なうようにするとよい。

また、温度・塩分以外のトレーサーに対する body forcing はデフォルトでは適用されないが、そのための書き換えは容易である。
具体的には `sfcng.F90` および `utint.F90` のしかるべき箇所を surface forcing の場合を参考に書き換えればよい
(これらのファイル中では必要な書換えが既に用意されており、コメントアウトされている)。

<a id="bound-time-interp"></a>

## 5. 境界条件の時間内挿について

境界条件の時間内挿を行なうためのツールは `utint.F90` に用意されている。使い方は
```fortran
CALL TMINTP(DITEM, IITEM)

REAL*8   DITEM(NXY) ! 出力される境界条件
INTEGER  IITEM*4    ! 境界条件の種類を指定するインデックス
```
であり、`IITEM` は海氷－海洋モデルでは

- 1～10: 「4. [境界条件ファイルについて](#bound-file)」に挙げた `TAUX`～`SSFC`
- 11以降の奇数: 各トレーサー (温度・塩分以外 )の海面緩和値
- 12以降の偶数: 各トレーサー (温度・塩分以外) の海面緩和係数

である。

body forcing のための時間内挿ルーチンは配列の大きさの部分を除いて境界条件のものと同じである。
これも `utint.F90` の中に含まれているが、これについては特に述べない。

### 5.1 内挿ルーチンの管理する情報

内挿ルーチンは次の値を保持し、随時更新する。

相対的に古い時刻に対応する
- ファイルに書かれた時刻の年月日時分秒表示 (`IDATE1`)
- データ (`DATA1`)
- 内挿の起点となる時刻の通算秒表示 (`TIME1`)

相対的に新しい時刻に対応する
- ファイルに書かれた時刻の年月日時分秒表示 (`IDATE2`)
- データ (`DATA2`)
- 内挿の終点となる時刻の通算秒表示 (`TIME2`)
```fortran
INTEGER IDATE1(6), IDATE2(6)
REAL*8   DATA1(NXY),  DATA2(NXY)
REAL*8   TIME1,  TIME2
```
それぞれの境界条件に対してこれらの値が用意される。
`TIME1` (`TIME2`) を年月日時分秒に変換した場合、そのうちの月日時分秒は `IDATE1` (`IDATE2`) の月日時分秒と一致する。
`TIME1` の年と `TIME2` の年の差は `IDATE1` の年と `IDATE2` の年の差に一致し、
モデル内部の現在時刻が `TIME1` と `TIME2` の間に入るようになっている。
`TIME1`, `TIME2` における年の具体的な決め方については後ほど述べる。

### 5.2 内挿

内挿ルーチンが呼ばれた時、現在時刻 (`TT`) が `TIME1` と `TIME2` の間に入っていれば、
その時点で保持しているデータを用いて時間内挿が行なわれる。すなわち、
``` fortran
((TIME2 - TT) * DATA1 + (TT - TIME1) * DATA2) / (TIME2 - TIME1)
```
によってその時刻における境界条件の値が求められる。

<a id="bound-time-interp-update"></a>

### 5.3 時刻とデータの更新

内挿ルーチンが呼ばれた時に `TT` が `TIME2` を過ぎていれば、時刻とデータの入れ替えを行なう。
このとき、まず
```
TIME1 = TIME2
IDATE1 = IDATE2
DATA1 = DATA2
```
とし、`IDATE2`, `DATA2` をファイルから読み込む。`TIME2` の月日時分秒は `IDATE2` のものと一致させる。
`TIME2` の年は `IDATE2` の年と `IDATE1` の年の差を `TIME1` の年に加えたものにする。

もし `IDATE2`, `DATA2` を読もうとした時に end of file であったら、rewind してファイルの先頭を読む。
`TIME2` の月日時分秒は `IDATE2` のものと一致させる。`TIME2` の年は
- `IDATE2` の月日時分秒が `IDATE1` の月日時分秒よりも前である場合には、
`TIME1` の年に `IYSKIP` (default は 1) を加えたものとする
- `IDATE2` の月日時分秒が `IDATE1` の月日時分秒よりも後である場合には、
`TIME1` の年に `IYSKIP - 1` を加えたものとする
によって決める。`IYSKIP` は実行時に読むパラメータファイルで指定できる。

<a id="bound-time-interp-init"></a>

### 5.4 最初の時刻とデータの決定方法 

内挿ルーチンが初めて呼ばれる時、`IDATE1`, `DATA1`, `TIME1` を決定しなければならない。
これはファイルに書かれた時刻の月日時分秒とモデルの現在時刻 (`TT`) の月日時分秒から決められる。

まずはファイルの先頭から `IDATE1` と `DATA1` を読み込む。`TIME1` については
- `TT` の月日時分秒がファイルの先頭の時刻の月日時分秒より後である場合には、`TIME1` の年を `TT` の年と一致させる
- `TT` の月日時分秒がファイルの先頭の時刻の月日時分秒より前である場合には、`TIME1` の年を `TT` の年の前年と一致させる
によって決定する。

続いてファイルから `IDATE2` と `DATA2` を読み込む。`TIME2` の決め方は「[時刻とデータの更新](#bound-time-interp-update)」で述べた方法と同じである。
このときに end of file であった場合には、時間内挿は行なわないものと判断する。

`TT` が `TIME1` と `TIME2` の間に入るまで、「5.3 [時刻とデータの更新](#bound-time-interp-update)」で述べたのと同じ方法によって時刻とデータを更新し続ける。
なお、ファイルの rewind が行なわれる回数は最大でも 1 回であり、その場合にはファイルの末尾が `IDATE1` に対応し、ファイルの先頭が `IDATE2` に対応するようになる。

この最初の時刻・データの決定方法と関連して、次のことを注意しておく。境界条件ファイルに書かれた年とモデルで管理している時刻の年を一致させたい場合、
モデルの積分開始時刻よりも前の時刻を境界条件ファイルの先頭に用意しなければならない。

## 6. 結果の出力について

ファイルに出力される結果としては

1. リスタートファイル
2. ヒストリーファイル

の二種類のものがある。リスタートファイルは初期条件ファイルと同じ形式で書かれており、長時間に渡る積分を何回かに分けて行なうために用いる。
ヒストリーファイルは積分結果の解析を行なうための出力である。

リスタートファイルは実行時のパラメータファイルでの指定により、積分中に定期的に書き換えられる。
その指定の仕方によらず、積分が正常に終了した場合には最終状態もリスタートファイルに書き出される。

以下ではヒストリーファイルについて説明する。

  - 等密度面拡散による温度フラックスの南北方向成分 (`FTYIS`) (degC cm^3/s/rad)
  - 等密度面拡散による温度フラックスの鉛直方向成分 (`FTZIS`) (degC cm/s)
  - 等密度面拡散による塩分フラックスの東西方向成分 (`FSXIS`) (psu cm^3/s/rad)
  - 等密度面拡散による塩分フラックスの南北方向成分 (`FSYIS`) (psu cm^3/s/rad)

  - 層厚拡散による bolus velocityの鉛直成分 (`WBOLUS`) (cm/s)

トレーサー (温度・塩分を含む) の水平フラックスは、
「速度×トレーサー濃度」に対してさらに「鉛直グリッド幅」と「フラックスに直交する方向の計量」がかけられた形で出力される。
次元は「長さの 3 乗÷時間×トレーサー濃度÷グリッド幅(ラジアン)」である。
フラックスに直交する方向の計量とは、例えば地理座標であれば、東西方向フラックスに対しては「地球の半径」、
南北方向フラックスについては「地球の半径×緯度の cosine」を意味する。
したがって、トレーサーの水平フラックスをそれと直交する水平方向に積分する場合には、
出力される各グリッドでのフラックス値に対してラジアンで表されたグリッド幅 (MASK の DX, DY) をかけて加えていくだけでよく、
計量をあらためて乗じてはいけない。
また、トレーサーの水平フラックスを鉛直積分する場合には、各グリッドでの値を単純に加えていくだけでよい。
トレーサーの鉛直フラックスにはグリッド幅や計量はかけられておらず、次元は「速度×トレーサー濃度」である。
海氷および海氷上雪のフラックスについても、ラジアンで表されたグリッド幅を乗じればフラックスと直交する水平方向の積分を求められる。

速度の鉛直成分について、`W` は sigma, z それぞれの鉛直座標で定義されたもので次元が異なる。
`WZC` は sigma 座標の範囲においても「長さ／時間」の次元を持つ鉛直速度にしたものである。

対流調節の頻度は、各瞬間においては対流調節が行なわれたグリッドに対しては 1 を、
行なわれなかったグリッドに対しては 0 を与える。
したがって、時間平均で出力を行なった場合には、その時間間隔における各グリッドごとの対流調節の頻度が 0 から 1 までの間の値で表される。
なお、最上層では常に 0 が与えられている。

各出力変数には出力項目名 (上の記述で括弧内に示したもの) が対応しており、出力の指定はその項目名によって行なう。
温度・塩分以外の、ユーザーが定義したトレーサーについては、
デフォルトでは `TRACER03`, `TRCFLX03` という名前で出力項目名が定義されている。
この最後の 2 桁の数字は 3 から `NTDIM` までの値をとる (FORTRAN の書式 I2.2)。

出力は

- 出力開始時刻
- 出力終了時刻
- 出力間隔
- 時間平均の有無
- 精度
- 出力範囲の経度方向始点
- 出力範囲の経度方向終点
- 出力範囲の緯度方向始点
- 出力範囲の緯度方向終点
- 出力範囲の鉛直方向始点
- 出力範囲の鉛直方向終点

を指定して行なう。これらはすべて出力項目ごとに別々の値を指定することができるが、
すべてに対するデフォルトの値を指定しておくと、項目ごとに特別に指定した場合以外にはそれが適用される。
このデフォルト値の設定はパラメータファイルにおける `&NMDOUT` で始まる行で行なう
出力開始・終了時刻はそれぞれ `IODSTR`, `IODEND` に年月日時分秒を指定する。
出力間隔は `IODINT` に間隔、`IUDINT` にその間隔の単位 (1:年, 2:月, 3:日, 4:時, 5:分, 6:秒)を与える。
その間隔について時間平均値を出力する場合には `IODAVR` に 1 を、
各間隔の最後の瞬間値を出力する場合には 0 を指定する。
また、出力を単精度実数で行なう場合には `IODSNG` に 1 を、倍精度実数で行なう場合には 0 を指定する。
例えば
```
IODSTR=1995,1,1,0,0,0
IODEND=1997,10,1,0,0,0
IODINT=1
IUDINT=2
IODAVR=1
IODSNG=1
```
であれば、「1995 年 1 月 1 日から 1997 年 10 月 1 日までについて、一カ月間隔で一カ月平均のデータを単精度実数で出力」
することをデフォルトとする。
出力範囲のデフォルトは全領域で、これはパラメータファイルで設定するようにはなっていない。

出力項目の選択はパラメータファイルの `COHITM` および `COHFIL` の指定によって行なう。
これは出力したい項目名とそれに対するファイル名をそれぞれ別の `&NMHIST` で始まるエントリーによって指定する。
例えば南北速度と温度をそれぞれ `u`, `t` というファイルに出力したいのであれば
```fortran
&NMHIST COHITM='U', COHFIL='u' &END
&NMHIST COHITM='T', COHFIL='t' &END
```
の 2 行をパラメータファイルに書く。指定する順序は問わない。
ただし、標準の状態では「6.3 [出力制御ルーチンの構造](#output-routine)」で述べられているバッファ領域が 3 次元変数 10 個の出力分の大きさしかとられていない。
したがって、それ以上のデータを同時に出力したい場合にはバッファ領域を大きくしなければならない。
その方法は「6.5 [メモリの節約方法](#output-memory)」で述べる。

出力開始時刻や出力範囲などがデフォルトのままでよければ、`COHITM` と `COHFIL` の指定だけで十分である。
ある項目に対してデフォルトとは異なる設定を与えたい場合には、その項目を指定した `&NMHIST` のエントリーに必要な指定を行なう。
指定は
```fortran
&NMHIST COHITM='T', COHFIL='t',
        IOHSTR=1998,10,1,0,0,0, IOHEND=1999,11,1,0,0,0,
        IOHINT=1, IUHINT=3, IOHAVR=0, IOHSNG=0,
        IOXSTR=51, IOXEND=150, IOYSTR=101, IOYEND=200, IOZSTR=3, IOZEND=5
&END
```
- `IOHSTR`: 出力開始時刻
- `IOHEND`: 出力終了時刻
- `IOHINT`: 出力間隔
- `IUHINT`: `IOHINT` の単位
- `IOHAVR`: 時間平均出力選択
- `IOHSNG`: 出力データ精度
- `IOXSTR`: 出力範囲の経度方向始点
- `IOXEND`: 出力範囲の経度方向終点
- `IOYSTR`: 出力範囲の緯度方向始点
- `IOYEND`: 出力範囲の緯度方向終点
- `IOZSTR`: 出力範囲の鉛直方向始点
- `IOZEND`: 出力範囲の鉛直方向終点

のように行なう。デフォルトから変更する必要がないものについては指定しなければよい。

### 6.2 出力形式

出力ファイルの形式は FORTRAN の書式なし形式で
```
ヘッダ1
データ1
ヘッダ2
データ2
…
```
となっている。これは
```fortran
CHARACTER CHEAD(64)*16 ! ヘッダ
CHARACTER CFMT*16      ! データ精度を表す文字列
INTEGER   NSIZE        ! データ長
INTEGER   IUNIT        ! ファイルの装置番号
REAL*8    VALUE(*)     ! データの値 (単精度出力の場合は REAL*4)

READ(IUNIT) CHEAD
CFMT = CHEAD(38)
READ(CHEAD(64), '(I16)') NSIZE
READ(IUNIT) (VALUE(I), I = 1, NSIZE)
```
で読むことのできる形式である。`CFMT` には単精度出力であれば `UR4` が、倍精度出力であれば `UR8` が入れられる。

ヘッダにはこの他にいくつかの情報が書き込まれている。CCSR/NIES AGCM で採用している GTOOL 形式に合わせてあるが、
GTOOL を使用するのに必要な情報が全て与えられているわけではない。書かれている情報は

- `CHEAD(1)` : 識別子 "9010"
- `CHEAD(3)` : 変数名
- `CHEAD(14:15)`: タイトル
- `CHEAD(16)`: 単位
- `CHEAD(25)`: 0年1月1日0時0分0秒との時間差
- `CHEAD(26)`: `CHEAD(25)` の単位
- `CHEAD(27)`: 時刻(yyyymmdd hhmmss ) (9 文字目と 16 文字目が空白)
- `CHEAD(28)`: 平均期間長 (単位は `CHEAD(26)` で指定、瞬間値なら 0)
- `CHEAD(29)`: `NX` + 'X' (例えば `NX = 128` ならば "128X" と書かれている)
- `CHEAD(30)`: 出力範囲の経度方向始点
- `CHEAD(31)`: 出力範囲の経度方向終点
- `CHEAD(32)`: `NY` + 'Y'
- `CHEAD(33)`: 出力範囲の緯度方向始点
- `CHEAD(34)`: 出力範囲の緯度方向終点
- `CHEAD(35)`: `NZ` + 'Z'
- `CHEAD(36)`: 出力範囲の鉛直方向始点
- `CHEAD(37)`: 出力範囲の鉛直方向終点
- `CHEAD(38)`: データフォーマット ("UR4", "UR4", "MR4" など、"UR4" は単精度、"UR8" は倍精度)
- `CHEAD(48)`: 平均期間始点時刻(yyyymmdd hhmmss ) (9 文字目と 16 文字目が空白)
- `CHEAD(49)`: 平均期間終点時刻(yyyymmdd hhmmss ) (9 文字目と 16 文字目が空白)
- `CHEAD(50)`: 時刻(yyyyyymmddhhmmss)
- `CHEAD(64)`: データ長

時刻は、瞬間値出力の場合はその時刻を、時間平均値出力の場合には平均期間の中央を表す。

### 6.3 出力制御ルーチンの構造

ヒストリーファイルの出力を制御するルーチン群は `qckot.F90` に用意されている。
また、出力のタイミングは `TMSTPC` (`atmct.F90`) で管理されている。

出力を指定された項目には項目番号 (NAMELIST 中で指定された順に 1 から) と装置番号が内部で与えられる。
割り当てられる装置番号は `zocfil.F90` の中で指定される `NFMIN` から `NFMAX` までであり、
初期条件ファイルや境界条件ファイルなどに割り当てられる装置番号もその中から取られる。
初期条件ファイルとマスキングファイルについては読み込み終了後ファイルが閉じられて装置番号が解放されるが、
境界条件・リスタートファイル・ヒストリーファイルに対する装置番号は確保されたままとなる。
装置番号の割当が限界を越えると、エラーで実行が終了する。装置番号の割り当ては `ufile.F90` で行なわれる。

それぞれの出力変数は、プログラム内の適当な箇所において出力用のバッファに変数を渡すためのルーチンに渡される。これは

```fortran
REAL(8)  DITEM(NDITEM) ! 出力項目に対応する変数
CHARACTER(*) CITEM     ! 出力項目名
CHARACTER(*) HTITL     ! 出力変数のタイトル
CHARACTER(*) HUNIT     ! 出力変数の単位
INTEGER NXITEM         ! 出力項目の東西方向次元配列長
INTEGER NYITEM         ! 出力項目の南北方向次元配列長
INTEGER NZITEM         ! 出力項目の鉛直方向次元配列長
INTEGER NDITEM         ! DITEM の全配列長
CHARACTER(*) CCLAS     ! 変数定義位置の識別子
CALL CHEKIN( DITEM, CITEM, HTITL, HUNIT, NXITEM, NYITEM, NZITEM, NDITEM, CCLAS)
```
によって行なわれる。`CCLAS` 変数が格子のどの位置で定義されているかを識別するもので AABBBC の6文字で構成されており、
- AA  : モデル要素 "OC" (海洋モデルの意味)
- BBB : 鉛直位置 "LVT"(格子中央), "LVM"(格子上面), "SFC"(水平2次元変数), "ICE"(海氷変数)
- C   : 水平位置 "T"(格子中央), "V"(格子北東隅), "X"(格子西面), "Y"(格子南面)

現在時刻が出力開始時刻を過ぎており、かつその項目を出力することが選択されている場合、
変数はバッファとなる配列の適当な箇所に加えられる (時間平均値出力の場合) もしくは上書きされる (瞬間値出力の場合)。
なお、バッファとして確保された領域は、出力を選択された項目に対して先頭から詰めて使用されるため、
出力したい項目を限定する場合には後述の方法によってメモリを節約することが可能である。
また、出力範囲を限定した場合、バッファに書かれるデータは鉛直方向に関しては出力範囲のみとなる
(水平方向には全領域のデータがバッファに格納される) ので、やはりメモリの節約が可能である。

ファイルへの出力は
```fortran
CALL CHKOUT(OFLOUT)
```
- `LOGICAL OFLOUT` : 出力のタイミングであるかどうかを示す flag

によって行なわれる。`TMSTPC` では次の出力を行なう時刻が管理されており、
現在時刻がその時刻を過ぎた時点で `OFLOUT = .TRUE.` にセットされると同時に次の出力時刻が求められる。
`OFLOUT = .TRUE.` で `CHKOUT` が呼ばれるとバッファの内容がファイルに書き出され、バッファはクリアされる。

### 6.4 出力項目の追加方法

出力項目を追加する場合には、既に存在するものと重ならない項目名をつけた上で、プログラム中の適当な場所で `CHEKIN` を呼べばよい。
`CHEKIN` はプログラム内のどこで呼んでも実行には差し支えないが、
時間積分に staggered time-steping 以外を用いる場合には `CHEKIN` を呼ぶ場所に関して注意が必要である。
すなわち、スナップショット出力の場合は問題ないが時間平均出力を行う場合
Euler-backward scheme で積分を行なっている時にバッファへの足し込みが 2 回行なわれてしまうことがある。
これを避けるためには

1. 出力する変数をルーチン `OCEAN` (`aocea.F90`) に持ってきて、そこで `CHEKIN` を呼ぶ
2. `CHEKIN` を呼ぶタイミングが 1 step が完全に終ってからになるように `OCEAN` において制御する
3. Euler-backward scheme を用いている時に backward step, forward step それぞれどちらにあるかを示す flag を用意し、
backward step では `CHEKIN` を呼ばないようにする

などの方法がある。

<a id="output-memory"></a>

### 6.5 メモリの節約方法

時間平均出力を全く行なわないのであればバッファは必要でない。
標準のモデルにおいては時間平均出力を行なうかどうかを実行時のパラメータファイルで指定できるようにしてあるので、バッファ領域が必ず確保される。
時間平均出力を行なわず、かつメモリの制約上バッファ領域を確保したくない場合には、それに応じたプログラム変更を行なえば良い
(そのためのオプションプログラムなどは、パッケージとしては用意しない)。

バッファとなる配列およびその大きさは module ファイル `zocout.F90` の中で指定されている。
配列長 `NWORK` は標準の状態では `10*NXYZ` になっており、出力可能な項目を全て同時に出力できるだけの大きさには取られていない。
したがって、同時に多くの項目の出力を行ないたいのであれば、それに応じて `NWORK` の値を大きくする必要がある。
なお、配列長が `NXYZ` を上回るような変数を出力項目にしたい場合には注意が必要である。

「時間平均出力は行ないたいが、全部の項目について出力する必要はない、あるいは出力範囲を限定するので、その分のメモリを節約したい」という場合には、
出力する項目から必要となるバッファの大きさを計算し、`NWORK` をその値に設定すればよい。
出力範囲を限定する場合、バッファを節約できるのは鉛直方向に関してのみであり、
水平方向に関しては常に全領域のデータがバッファに格納されるので注意すること。
また、改めて注意しておくが、時間平均出力を行なうか否かにかかわらず、ある項目について出力を選択すれば、
その変数の配列長の分のバッファ領域が必要である。

### 6.6 密度座標への結果の出力について

本バージョンでは、3次元変数の一部を予め定義した密度座標で出力することができる。
現状、変数の鉛直配置がグリッド中点・水平配置が T 点または V 点の変数が対応している。
それ以外の変数を密度座標出力した場合の結果は保証されない。

密度座標出力を行う場合、以下の形式で読める密度座標系の定義ファイルを用意する。

```fortran
INTEGER, PARAMETER :: NNC = 1  !! 含まれる密度座標系の数
INTEGER, PARAMETER :: NSIGMX = 106  !! 層数の最大値

CHARACTER*16 :: CNAME(NNC)  !! この密度座標系の識別名
INTEGER :: NSIG(NNC)        !! この密度座標系の層数
REAL*8 :: ZREF(NNC)         !! この密度座標系の基準深度 [cm]

REAL*8 :: LSIG(NSIGMX,NNC)      !! 密度座標系の定義点
REAL*8 :: LSIGP(NSIGMX+1,NNC)   !! 密度座標系の層境界
REAL*8 :: DSIG(NSIGMX,NNC)      !! 密度座標系の層厚
! DSIG(K,N) = LSIGP(K+1,N) - LSIGP(K,N)

READ(21) NNC
READ(21) CNAME
READ(21) ZREF
READ(21) NSIG
READ(21) LSIG
READ(21) LSIGP
READ(21) DSIG
```
`extra/SCOORD/make_SCOORD.f` にこのファイルを生成するサンプルプログラムが用意されている。

用意した定義ファイルをパラメータファイルで指定し、密度座標出力を有効化する。
```fortran
&NMSGCO CFSGCO='SCOORD' &END
```
ここで `CFSGCO` として指定された定義ファイルが見つからない時、あるいは単に指定しなかった場合は、密度座標出力は無効化される。

実際の出力は、`NMHIST` での出力設定に密度座標系の識別名を `COHVCO` として与えることで行う。
`COHVCO` が指定されない場合、あるいは密度座標出力が無効化されている場合は、その変数は通常通り z 座標系で出力される。
```fortran
&NMHIST COHITM='T', COHFIL='to_sig2',
        COHVCO='sigma2_l106', IOSVIN=0 &end
```
`IOSVIN` として 1 を指定すると、指定された変数に各密度層の層厚を乗じた値が出力される。
たとえば密度座標系で出力した流速を用いて子午面流線関数を描く場合などに有効である。
なお、`IOSVIN = 0` かつ時間平均出力を指定した場合、
各タイムステップでの密度層の層厚で重みづけされた時間平均値が出力されることに注意が必要である。

以下の 2 つの出力変数は、密度座標出力の設定に対して特殊な挙動をする。
- `PDEN` (ポテンシャル密度): `COHVCO` を与えない場合は基準深度を 0 cm (海面)として計算した値を、
与えた場合はその密度座標系の基準深度で計算した値を、それぞれ出力する。
いずれの場合も z 座標系で出力される。IOSVIN の値は無視される。
なお、海面を基準深度とするポテンシャル密度は、密度座標出力の有効無効にかかわらず出力可能である。
- `DZSIG` (密度層の層厚): 有効な `COHVCO` が与えられない場合、出力指示自体が無視される。`IOSVIN` の値は無視される。

## 7. 非標準スキームについて

`src/option/` に存在する非標準プログラムは、コンパイル時に `Mkinclude` において
```
SRCOPT = dvdif.nk
```
などとすることによって使用することができる。
以下のリストで、同一の項に 2 つ以上のルーチン名が挙げられている場合、そのスキームを利用するには全てのルーチンを `SRCOPT` に記述する。
また、設定するルーチンのうちのいくつかは、モデルの選択 (`MODEL`) に応じて実際に適用すべきルーチン名が異なることに注意せよ。

なお、以下のスキームの中には、(主として歴史的理由から) 非標準スキームとされてはいるが事実上の標準となっているものもいくつか存在する。
具体的には `tflxt.ut` と `dvdif.nk` が該当する。
通常の使用では、同種の異なるスキーム (たとえば `dvdif.nk` の代わりに `dvdif.gls`) を用いない限り、これらのスキームを用いることを強く推奨する。

### トレーサー移流・(水平)拡散

#### tflxt.ut

トレーサーの拡散に等密度面拡散および Gent et al. (1995) による isopycnal layer thickness diffusion を、
移流に UTOPIA/QUICKEST (水平 2 次元に関して UTOPIA, 鉛直に関して QUICKEST) を適用する。
指定すべきパラメータは
```fortran
&NMDIFI AHI=1.D+7 &END
&NMDIFG AHG=1.D+7 &END
```
- `AHI`: 等密度面拡散係数 (cm^2/s)
- `AHG`: thickness diffusion 係数 (cm^2/s)

```fortran
&NMSLPM SLPMAX=1.D-2 &END
```
- `SLPMAX`: 等密度面の水平面からの傾きの最大値。`SLPMAX` は指定されなければ 0.01 がデフォルト値として使われる。

通常の Laplacian 水平拡散も同時に適用され、その係数は [2.7](#setup-parameter) に挙げた `AHH` で指定する。
`AHG = 0` とすると拡散部分は単なる等密度面拡散になる。thickness diffusion を用いる場合と用いない場合の間で計算量は全く変わらない
(用いない場合に余分な計算をしているという意味ではない)。

`AHI = AHG = 0` として `AHH` のみを指定すれば単純な水平拡散ルーチンとして用いることができるが、
この場合には等密度面拡散に関する計算が省略されるわけではないので、無駄な計算をすることになる。

トレーサーの水平拡散を biharmonic で扱い、移流に UTOPIA/QUICKEST を用いる場合には、以下のパラメータを指定する。
```fortran
&NMDIFB AHB = 1.D+18 &END
```
- `AHB`: Biharmonic 拡散係数

通常の Laplacian 拡散を適用しない場合は、 `AHH = 0` を指定する必要がある。

Fox-Kemper et al. (2008) の mixed layer eddy parameterization を適用する場合は以下のパラメータを指定する。
```fortran
&NMMLEP OMLEP = T &END
```
実装は Fox-Kemper et al. (2011) の coarse resolution model への修正を含んでいる (この修正を含んでいても、高解像度設定でも問題なく使用できる)。
指定できるパラメータはいろいろあるが、通常はデフォルト値でよい。ただし後述の鉛直混合層スキームの設定と対応させる形で
```fortran
&NMMLEP MZ=22 &END
```
- `NMMLEP`: mixed layer eddy parameterization を適用する最深の level

を設定してもよい。

#### tflxt.som
`tflxt.ut` のうち、移流に second order moment scheme (Prather, 1988) を用いる。
他の指定すべきパラメータは `tflxt.ut` の項を参照のこと。

#### tflxt.som.scalar
`tflxt.som` にスカラー機用のチューニングを施したもの。他の指定すべきパラメータは
`tflxt.ut` の項を参照のこと。


### 鉛直混合／鉛直対流

#### dvdif.nk

Noh and Kim (1999, JGR) の turbulence closure を適用する。ただし、様々な変更を加えてある。
指定できるパラメータも多数あるが、通常は
```fortran
&NMDVNK MZ=9 ALPH=120 &END
```
- `MZ`: turbulent closure scheme を適用する level 数

以外はデフォルトを用いる。詳しくは COCO4 documentation を参照。

指定した緯度より赤道よりで TKE の消散率を高くする場合、以下を設定する。
```fortran
&NMDVNK OC0LAT=T, LATCEQ=5.0D0, LATC0=15.0D0,
        C0=0.06D0, C0EQ=0.6D0 &END
```
- `OC0LAT`: 指定した緯度より赤道寄りで TKE の消散率を高くする場合 T を指定する。 
- `LATCEQ`, `C0EQ`: 緯度の絶対値が `LATCEQ` より小さい場所で、消散率を決める係数として `C0EQ` を用いる。
- `LATC0`, `C0`: 緯度の絶対値が LATC0 より大きい場所で、消散率を決める係数として `C0` を用いる。
`LATC0` から `LATCEQ` の間は、線形に補間する。

エネルギー散逸率の水平2次元分布と成層を考慮して鉛直拡散係数の3次元分布を計算して与えるには、
以下のパラメータを指定する。
```fortran
&NMDVED IAMN = 1, IAMF = 1, CFTEDN="TEDN", CFTEDF="TEDF", CGAMMA=0.2, ZETA=500.D0,
        OFVCNT = F, OFVPN = F &END
```
- `IAMN`: 0以外を指定した場合、局所的なエネルギー散逸率の2次元分布を適用する。
- `IAMF`: 0以外を指定した場合、遠隔的なエネルギー散逸率の2次元分布を適用する。
- `CFTEDN`: 励起源付近での局所的なエネルギー散逸率の水平2次元分布のファイル名
- `CFTEDF`: 励起源から遠い場所での遠隔的なエネルギー散逸率の水平2次元分布のファイル名
- `CGAMMA`: 混合効率 (mixing efficiency)。
- `ZETA`: 局所的エネルギー散逸のスケールハイト (単位は m)。
- `OFVCNT`: `.TRUE.` の場合、遠隔的なエネルギー散逸率を鉛直一様に分布させる (Oka and Niwa, 2013, Nature Comm.)。
`.FALSE.` の場合は `OFVPN` の設定に従う。
- `OFVPN`: `.TRUE.` の場合、遠隔的なエネルギー散逸率の鉛直分布を浮力振動数に比例させ、
`.FALSE.` の場合は浮力振動数の二乗に比例させる (Kawasaki et al., 2021, JO)。

ここで与えているエネルギー散逸率の分布は、
潮汐モデル (e.g., Niwa and Hibiya 2014, OM) の計算結果などを基に別途用意する必要がある。

#### dvdif.gls
混合層モデルの一種である Umlauf and Burchard (2003, JMR) の generic length scale parameterization を適用する。
ここでの実装には、Carniel et al. (2009, OM) に従って砕波による TKE input の効果が加えられている。
多くのパラメータがあるが、通常指定すべきは以下の値である。
```fortran
&NMDVGL OSFCWV=T, OSWNOI=T, OBTKEI=f, TKEMIN=3.0D-2 &end
```
- `OSFCWV`: 海面での砕波による TKE input を考慮する場合 `.TRUE.` を指定する。
- `OSWNOI`: `.TRUE.` の場合海氷下では砕波による TKE input を与えない。`OSFCWV=T` の時のみ有効な設定。
- `OBTKEI`: 海底でも摩擦に応じて TKE input を与えるかどうか。
- `TKEMIN`: TKE のバックグラウンド値。このルーチンで予報される TKE の最小値として用いられる。

他の指定すべきパラメータは `dvdif.nk` の項を参照のこと。

### 水平粘性

#### cvisc.smag

Smagorinsky (1963, MWR) による、速度依存の粘性係数を適用する。指定すべきパラメータは
```fortran
&NMSMAG    CSM=3.D0,    CSMB=0.D0 &END
&NMSMGB CSMBBL=3.D0, CSMBBBB=0.D0 &END
```
- `CSM`: 粘性係数を (CΔ/π)^2 D とするときの C。ここでΔは水平格子間隔 (東西・南北のうち小さい方。緯度依存)で、
D は 1/s の次元を持つ deformation rate。詳しくは Griffies and Hallberg (2000, MWR) を参照のこと。
- `CSMBBL`: `CSM` に同じ. ただし BBL における係数。
- `CSMB`: Smagorinsky の方法を biharmonic 水平粘性の形で適用した場合の、Harmonic Smagorinsky で与える `CSM` と同じ。
粘性係数は (CΔ/π)^2 D * Δ^2 / 8 で与えられる。詳しくは Griffies and Hallberg (2000, MWR) を参照のこと。
- `CSMBBB`: `CSMB` に同じ. ただし BBL における係数。

### tunnel diffusion

tunnel diffusion とは、指定した 2 つのグリッド間でトレーサー及び海面高度を拡散的に交換するスキームのことである。
通常は、解像度不足で陽に表現できない海峡を介しての水のやりとりを、モデルの陸グリッド越しに実現するために用いられる
(とは言え、実装上は陸グリッド越しでなくとも、さらには隣り合ったグリッド間であろうとも適用は可能である。
そうする意味は無いと思うが…。)。
パラメータとしては以下を指定する。
```fortran
&NMTUNL ITUN1  = 294,   125,
        JTUN1  = 128,   154,
        ITUN2  = 299,   125,
        JTUN2  = 128,   157,
        LEVTUN =  30,    11,
        DMPTUN = 3.D2, 3.D2,
        DSHTUN = 1.D2, 1.D2 &end
```
- `ITUN1`, `JTUN1`, `ITUN2`, `JTUN2`: グリッド `(ITUN1, JTUN1)` と `(ITUN2, JTUN2)` の間で tunnel diffusion を適用する。
- `LEVTUN`: トレーサー交換を適用する level の下限。海面から指定された level まで、各トレーサーが各層ごとに拡散的に交換される。
- `DMPTUN`: トレーサー交換に用いられる時定数 (日)
- `DSHTUN`: 海面高度 (=水量) の交換に用いられる時定数 (日)

以上すべての項目は複数の値を指定可能で、その場合には各項目の 1 番目同士、2 番目同士、…を組として tunnel diffusion が適用される。
したがって例示の設定の場合は、
- (294, 128) と (299, 128) の間で tunnel diffusion が適用される。
トレーサーは表層から 30 層目まで適用対象で、交換の時定数は 300 日。海面高度の交換の時定数は 100 日。
- (125, 154) と (125, 157) の間で tunnel diffusion が適用される。
トレーサーは表層から 11 層目まで適用対象で、交換の時定数は 300 日。海面高度の交換の時定数は 100 日。

という 2 組の tunnel diffusion が独立に適用されることになる。もちろん、1 組のみの設定でも動作に問題はない。

### 境界条件
#### sfcng.CORE, utint.CORE

CORE (Large and Yeager, 2004)のプロトコルに沿った境界条件を与える。
このスキームを用いる場合、境界条件ファイルとして以下を用意する。

- `USFC`: 海上 10m 風速東西成分 (m/s, 東向きが正)
- `VSFC`: 海上 10m 風速南北成分 (m/s, 北向きが正)
- `TSFC`: 海上 2m 気温 (K)
- `QSFC`: 海上 2m 比湿 (nondimensional)
- `SWDW`: 海面における下向き短波放射 (W/m^2, 正値)
- `LWDW`: 海面における下向き長波放射 (W/m^2, 正値)
- `P+R`:  海面における淡水流入フラックス (降水と河川流入の和) (m/s, 海面から淡水が抜かれる向きが正、通常は負値)
- `SFLX`: 海面における降雪フラックス (m/s [水換算]、海面から淡水が抜かれる向きが正、通常は負値)
- `PSFC`: 海面気圧 (Pa)

書式は標準と同様であり、全てのデータは海洋の T-点上で値が定義されて
いるとみなされることも同様である。海面で塩分の緩和を行なう場合には、
やはり標準ルーチンと同様、

- `SSFC`: 海面塩分 (psu)

も必要になる。

このルーチンでは、淡水フラックスのうちの蒸発・昇華フラックス、熱フラックスのうちの上向き短波・長波フラックスと潜熱・顕熱フラックス、
および風応力は bulk formulae を用いて計算される。
特に淡水フラックスの一部が診断的に与えられることから、一般にモデルの水の全量は保存しないことに注意すること。

標準的に与えるべきパラメータは以下の通りである
(アルベドに関するパラメータは多岐に渡るためここでは代表的なものについてのみ説明する、詳細はコードを見よ)。
```fortran
&NMSFBC CFUSFC='USFC', CFVSFC='VSFC', CFTSFC='TSFC', CFQSFC='QSFC',
        CFSWDW='SWDW', CFLWDW='LWDW', CFPPLR='P+R',  CFSFLX='SFLX',
        CFPSFC='PSFC', CFSSFC='SSFC' &END
&NMSWEM OASOLD = T, ALBSWO = 0.066D0 &END
&NMICE  ALBICE=0.5D0,0.5D0,0.05D0 &END
&NMSNOW ALBSNW=0.75D0,0.5D0,0.75D0,0.5D0,0.0D0,0.0D0,
        TALSNW=258.15D0,273.15D0      &END
&NMSFRC OASFRC=F, ALSDPT=1.0D0, ALSPAT=2.0D0 &END
&NMSAGE OSAGE=F, ALSSIF=0.75D0,0.75D0,0.0D0
                 ALSSIO=0.5D0,0.5D0,0.0D0 &END
&NMMPND IMPND=0, ALBMPD=0.4D0,0.1D0,0.0D0,
                 ALMPDP=0.5D0, 20.0D0 &END
```
- `CFUSFC`, `CFVSFC`, `CFTSFC`, `CFQSFC`, `CFSWDW`, `CFLWDW`, `CFPPLR`, `CFSFLX`, `CFPSFC`, `CFSSFC`: 境界条件ファイル名。

順に、海上風速東西成分、海上風速南北成分、海上気温、海上比湿、海面下向き短波放射、
海面下向き長波放射、海面淡水流入フラックス、海面降雪フラックス、海面気圧、海面塩分のファイル名。
- `OASOLD`: ocean albedo として Larde and Yeager (2009, CD) の緯度依存性を持つ値を採用するとき `.TRUE.` を指定する。この場合、次項 `ALBSWO` の設定は無効となる。
- `ALBSWO`: `OASOLD=F` の時、ocean albedo の値 (ND)。
- `ALBICE`: 積雪のない海氷のアルベドの値 (ND)。

波長帯別になっており、順に可視光 (以下 VIS と表記)、近赤外 (以下 NIR と表記)、長波 (以下 IR と表記) での値を設定する。
この値は以下でのスキーム選択に依らず参照される。
- `ALBSNW`, `TALSNW`:

`OSAGE = F` の時の海氷上積雪のアルベド値を設定する。
このスキームは MIROC6 および COCO4 までで使われてきたものと同一である。
`ALBSNW` は積雪のある海氷のアルベドの値 (ND)。
値は 2 つずつの組となっており、最初の 2 つが VIS、次の 2 つが NIR、最後の 2 つが IR の設定である。
それぞれの組の先の値でその波長帯でのアルベドの最大値、後の値で最小値を設定する。
モデル中でのアルベドは積雪の表面温度に依存し、その依存性を `TALSNW` (単位 K) で設定する。
表面温度が `TALSNW` の 1 つめの値より低い時、アルベドは設定した最大値を取る。
2 つめの値より高い表面温度の時、アルベドは最小値を取る。
その間の温度は線形に補間した値がアルベドとして用いられる。
- `OASFRC`, `ALSDPT`, `ALSPAT`: 海氷上アルベドを求める際の積雪被覆率の決め方を設定する。

`OASFRC=F` の時は MIROC6/COCO4 までと同一のスキームを用いる。
すなわち、積雪が `ALSDPT` (cm) 以上の時海氷は全て積雪に覆われ、それ未満では積雪のない海氷とみなす。
`OASFRC=T` の時は、積雪 `Hs` (cm) の被覆率を `Hs/(ALSPAT+Hs)` とする (`ALSPAT` の単位は cm)。
- `OSAGE`, `ALSSIF`, `ALSSIO`: 積雪アルベドの決め方を設定する。

`OSAGE=F` の時、前述の通り `ALBSNW` と `TALSNW` を用いて積雪アルベドを決める。
`OSAGE=T` の時、積雪アルベドは経験した温度と大気から降下するダスト量に依存して、時間と共に低下する。
新雪のアルベドを `ALSSIF` (ND)、変質した積雪のアルベド最低値を `ALSSIO` (ND) で設定する。
それぞれ VIS, NIR, IR の 3 つの値をこの順に与える。
また `OSAGE=T` の時、リスタートファイルに規格化された積雪の年齢が追加出力される。
なお、現状の COCO の実装では降下ダスト量を陽に与えることはできず、dirt factor で一様な変質速度を設定している。
詳しくはコードを参照のこと。
- `IMPND`, `ALBMPD`, `ALMPDP`: 海氷上のメルトポンドの効果を設定する
  - `IMPND = 1`: Holland et al. (2012) を元にした定式化を使用する
  - `IMPND = 2`: Hunke et al. (2013) を元にした定式化を使用する

前者の方が簡便な定式化で、後者では ridging 等による氷の力学的変形の考慮
(メルトポンドは変形を受けていない level ice 上のみに存在できる)、
積雪とメルトポンドの共存領域の表現、もろい氷からのメルトポンド水漏出の表現などより複雑なプロセスが含まれる。
ただし、メルトポンドの再凍結過程については `IMPND=2` の場合でも Holland の定式化を用いている。
いずれの定式化でも、メルトポンドの深さが ALMPDP (cm) の 1 つめの値以下の時、
メルトポンドのアルベドは積雪のない海氷の値に等しい。
深さが `ALMPDP` の 2 つめの値以上の時、アルベドは `ALBMPD` となる (順に VIS, NIR, IR の値)。
その間の深さでは、線形に補間した値がメルトポンドのアルベドとなる。
また `IMPND=1, 2` の時、リスタートファイルに level ice 比率、メルトポンド深さ、メルトポンド被覆率の 3 つが追加出力される。
`IMPND=0` の時、メルトポンドのアルベドは深さによらず積雪のない海氷の値に固定される (メルトポンドのアルベドへの影響を考慮しないことに相当する)。

#### 以前のアルベド設定からの移行方法について
2021 年 6 月の更新以前は、海氷のアルベドおよび放射率は以下のように設定していた。
```fortran
&NMLWEM OLWNET = F, EMISLO = 1.0D0, EMISLI = 0.95D0    &END
&NMSWEM OSWNET = F, ALBSWO = 0.066D0, ALBSWI = 0.5D0,
        ALBSWS = 0.75D0,0.5D0, ALSWST = -15.0D0, 0.0D0 &END
```
このうち `EMISLI`, `ALBSWI`, `ALBSWS`, `ALSWST` は現在のコードからは削除されている。
これらの値を順に `Em`, `Ai`, `(As1, As2)`, `(At1, At2)` とすると、以下のように設定することで過去と同一の設定で実験を行うことができる。
- `OASFRC=F`, `OSAGE=F`, `IMPND=0`
- `ALBICE=Ai, Ai, (1-Em)`
- `ALBSNW=As1, As2, As1, As2, 0.0D0, 0.0D0` (`ALBSNW` の IR の設定値は現状雪面の放射率としては参照していない)
- `TALSNW = (At1+273.15), (At2+273.15)`
- `ALSDPT` を陽に与えている場合は、`NMSWEM` から `NMSFRC` に移動する。

#### sfcng.CORE.direct, sfcng.JRA.direct, utint.CORE.direct, utint.JRA.direct

CORE (Large and Yeager, 2004) のプロトコルに沿った境界条件を、オリジナルデータの座標系で与える。
境界条件として CORE データセットを与える場合は `sfcng.CORE.direct` と `utint.CORE.direct` を、
JRA55-do データセット (Tsujino et al., 2018) を与える場合は `sfcng.CORE.direct` と `utint.JRA.direct` を用いる。
現在 `sfcng.CORE.direct` および `utint.CORE.direct` は未実装である。
なお、このスキームを使用する際には、拡張マスキングファイル (詳細は [2.1 節](#setup-os)と [2.6 節](#setup-compile)) を用いる必要がある。

標準的に与えるべきパラメータは `sfcng.CORE`, `utint.CORE` と同様だが、以下のネームリストのみ異なる
```fortran
&NMSFBC CFUSFC='USFC', CFVSFC='VSFC', CFTSFC='TSFC', CFQSFC='QSFC',
        CFPREC='RAIN', CFSFLX='SNOW', CFSWDW='SWDW', CFLWDW='LWDW',
        CFPSFC='PSFC', CFROFF='ROFF', CFSSFC='SSFC',
        GRID_JRA='GRID_JRA', ROFF_MAP='ROFF_MAP', OLINT_WIND=F &END
```
- `CFUSFC`, `CFVSFC`, `CFTSFC`, `CFQSFC`, `CFPREC`, `CFSFLX`, `CFSWDW`, `CFLWDW`, `CFPSFC`, `CFROFF`, `CFSSFC`: 境界条件ファイル名

順に、海上風速東西成分、海上風速南北成分、海上気温、海上比湿、海面降水フラックス、海面降雪フラックス、
海面下向き短波放射、海面下向き長波放射、海面気圧、海面河川流入フラックス、海面塩分のファイル名。
すべて、データセットオリジナルの座標系・単位系・正負の向きで用意する。
通常の、モデルの座標系で境界条件ファイルを与える場合とは、いくつかの要素で単位等が異なることに注意
(下記の `&NMTRDB` についての説明を参照のこと)。

- `GRID_JRA` (または `GRID_CORE`): データセットの座標系情報を格納したファイル名。

ファイルは FORTRAN の書式なし形式で以下のように読まれる。
```fortran
INTEGER   :: IUNIT   ! ファイルの装置番号
INTEGER, PARAMETER :: NX0 = 640, NY0 = 320  ! JRA データ格子数
REAL*8 :: ALON(NX0), ALAT(NY0) ! JRA データの緯度経度情報(ラジアン)
INTEGER :: MASK(NX0,NY0) ! マスク

READ(IUNIT) ALON
READ(IUNIT) ALAT
READ(IUNIT) MASK
```
`MASK` が 0 のデータは、海面境界条件の補間に用いない。
例えば、海洋モデルの海面境界条件として JRA 再解析モデル内で陸上に相当する大気情報を補間に用いないためには、
海上を 1、陸上 0 となる2次元データを与えておく。
省略した場合はすべて 1 が仮定され、すべてのデータを海面境界条件の補間に用いる。

- `ROFF_MAP`: 海面河川流入フラックスがモデルグリッドにどう分配されるかの情報を格納したファイル名。

ファイルは FORTRAN の書式なし形式で以下のように読まれる。
```fortran
INTEGER   :: IUNIT   ! ファイルの装置番号
INTEGER   :: IMAX    ! JRA 河川データ格子とモデル格子の対応デーブル数
INTEGER, ALLOCATABLE :: IP(:), JP(:)  ! JRA 河川データ格子位置
INTEGER, ALLOCATABLE :: IQ(:), JQ(:)  ! モデル格子位置
REAL*8 :: WT(:) ! 分配率(無次元; 任意)

READ(IUNIT) IMAX
ALLOCATE(IP(IMAX), JP(IMAX), IQ(IMAX), JQ(IMAX), WT(IMAX))
READ(IUNIT) IP
READ(IUNIT) JP
READ(IUNIT) IQ
READ(IUNIT) JQ
READ(IUNIT) WT
```
例えば、以下のように指定すると、JRA 河川データの(10,20)の位置に格納されている河川流入量は、
モデル格子の(30,40)の位置の流入量として適用される。
```
IP(1) = 10, JP(1) = 20, IQ(1) = 30, JQ(1) = 40
```
また、以下のように指定すると、JRA 河川データ格子(10,20)の河川水が
モデル格子 (29,40) と (31,40) に 1/4 ずつ、(30,40) に 1/2 分配される。
```
IP(1) = 10, JP(1) = 20, IQ(1) = 29, JQ(1) = 40, WT(1) = 0.25D0
IP(2) = 10, JP(2) = 20, IQ(2) = 30, JQ(2) = 40, WT(2) = 0.5D0
IP(3) = 10, JP(3) = 20, IQ(3) = 31, JQ(3) = 40, WT(3) = 0.25D0
```
分配率 `WT` は任意で、データが存在しない場合はすべて 1 (河川流量すべてがモデル格子に適用) となる。

`GRID_JRA` と `ROFF_MAP` については、`TOOL` 以下に作成ツールが用意される予定 (未実装)。

- `OLINT_WIND`: `.TRUE.` の場合、東西・南北風速を線形補間にする。低解像度モデルで計算負荷を軽減する。

風速を線形補間した場合、風速の空間勾配が不連続に変わるため、不自然なエクマン輸送・鉛直流が生じてしまう。
それを回避するため、デフォルトでは風速にスプライン補間を用いるが、線形補間に比べて計算負荷が大きい。
一方、JRA の風速データの空間解像度は 0.5 度程度であるため、
低解像度モデル (例えば全球1度モデルなど) では風速を線形補間しても支障ない。

```fortran
&NMTRDB TRDBCP=F &END
```
- `TRDBCP`: 境界条件をオリジナルの座標系で与える際の単位系・正負の向き。

F の時は、データセットオリジナルと同様。
T の時、モデルの座標系で与える際と同様。具体的には、以下の境界条件ファイルが影響を受ける。
JRA55-do の場合 (`utint.JRA.direct.F90`):
- `TRDBCP = F` : `PREC`、`SNOW` は単位 kg/m^2/s、ROFF は単位 kg/s、海面に入る向きを正 (通常は正値となる)。
- `TRDBCP = T` : `PREC`、`SNOW` は単位 m/s (水換算)、ROFF は単位 m^3/s、海面から出る向きを正 (通常は負値となる)。

```fortran
&NMSFYR OTYEAR=F &END
```
- `OTYEAR`:

directルーチンでは、デフォルト (`OTYEAR = F`) では境界条件ファイルに記された時刻の年の値に意味があり、
例えば境界条件ファイルで2000年となっているデータでモデル年が1900年の実験を駆動することはできない。
`OTYEAR = T` の時は、境界条件ファイルに記された時刻の年をモデル年と読み替える。
具体的には：
- 境界条件ファイルの最初のデータの年を Y1、積分開始時刻の年を Ys とする。
- 境界条件ファイルの最初のデータの時刻と積分開始時刻を年を無視して比較し、境界条件ファイルの時刻の方が早いもしくは同時の場合、Y1 を Ys に読み替える。
- 境界条件ファイルの時刻の方が遅い場合、Y1 を Ys-1 に読み替える。
- 境界条件ファイルの2つめ以降のデータの年 Yn は、Y1 を読み替えた値 (Ys もしくは Ys-1) に Yn-Y1 を加えた値に読み替える。

したがって `OTYEAR = T` の時、境界条件の年は[4.2節](#bound-file-time-interp)で説明されているモデル標準の挙動に近い解釈をされる
(ただし、ファイル末尾のデータの後に先頭のデータが続くとみなすことはしない)。
このオプションは、JRA55-doなどのデータを繰り返し与えて長期積分を行う場合など、境界条件の年とモデル年が異なる場合に有用である。

## 8. 並列化における基本発想
### 8.1 入出力

現在のところ初期条件・境界条件・実行結果の入出力はあるひとつのノードでまとめて行なう。
解像度を高めていくとメモリの制約から各ノード毎に入出力を行なう必要が生じることも考えられ、
必要に応じてこの方法は改められるかもしれない (実際、MPI-IO や NetCDF 出力では、各ノード毎に入出力を行っている)。

入出力を行なうノード番号 (rank) は実行時のパラメータファイルにおいて、`NAMELIST /NMROOT/` の `NDROOT` という変数で指定される。
デフォルトでは 0 が与えられている。
`NDROOT` は 0 から `NPROCS-1` (`NPROCS` は MPI プログラムの実行時に指定するノード数) までのどの値にしても正常に動作する。

実行時のパラメータファイルの読み込みはすべてのノードで行なう。

### 8.2 通信における注意点

領域分割は東西・南北の二方向に存在するので、通信も東西・南北の二方向に関して必要である。
各領域はその東西南北端の外に 2 グリッドの領域を持ち、そこに通信によって境界条件を入れる。
すなわち、各ノードにおける水平方向のグリッド配置においては
```
    ZZYYYYZZ
    ZZYYYYZZ    O: このノードにおける計算領域
    XXOOOOXX    X, Y, Z: 通信によって取得する境界条件の領域
    XXOOOOXX
    ZZYYYYZZ
    ZZYYYYZZ
```
のようになっている。
ここで X で表されたグリッドには東西方向の通信で、Y で表されたグリッドには南北方向の通信で境界条件を入れるのであるが、
モデルでは Z で表されたグリッドにも境界条件を入れる必要がある。
その方法のひとつとして斜め方向に通信を行なうということが考えられる。
このように東西・南北・斜めを別々に通信する場合、通信の順序は問われない。
ここでは通信回数を減らすという観点から次のようにする。
まず、東西方向の通信によって X で表されたグリッドに境界条件を入れる。
この通信が終了してから、南北方向の通信によって Y, Z で表された方向の通信を行なう。
東西方向の通信が終了しているので、Z で表されたグリッドには斜め方向にある領域のデータが取得される。

1 対 1 通信はノンブロッキング通信によって行なっているが、
現在、すべてのノンブロッキング通信において `SEND`, `RECV` の直後にその通信に対する `WAIT` を呼んでいる。
先ほど述べた通り、東西方向の通信が終了して受信バッファの内容を X のグリッドに入れた後でなければ南北方向の通信を行なうことができない。
したがって東西方向の通信に関しては `SEND`, `RECV` の直後に `WAIT` を呼ぶ必要がある。
一方、南北方向の通信に関しては `SEND`, `RECV` を呼び、そのまま処理を続行し、
変数が必要とされる直前になって `WAIT` を呼び、受信バッファの内容を Y, Z のグリッドに入れるということもできる。
ここでそのようにしなかった理由は主にプログラムの読みやすさのためである。
本来は `WAIT` を呼ぶのをぎりぎりまで待つのが正しい。
少なくともそうすることによって実行速度が低下することはない。
また、斜め方向の通信を採用すれば、すべての 1 対 1 通信において `WAIT` を呼ぶのをその変数が必要とされる直前まで遅らせることができる。
しかし、実際の通信における律速段階は通信速度そのものよりもサブルーチンコールにおけるソフトウェア的な部分にあると言われているので、
ここではプログラムの読みやすさを優先した。

### 8.3 通信のための境界領域の幅について

前述の通り、このモデルでは通信によって隣のノードの情報を受け取るための境界領域が 2 グリッドずつ設けられている。
この 2 という数は現在のところ
- 外部モードの time splitting において通信回数を減らすため
- 移流スキーム UTOPIA を使うため
- Biharmonic diffusion を使うため
という要請から決まっている。この幅は xmkmsk.F で明示的に与えられている。
すなわち、各ノードで定義された水平領域において、
境界領域ではない領域の東西方向の先頭グリッド `ISTR` および南北方向の先頭グリッド `JSTR` がともに 3 で与えられており、
東西方向の境界領域の幅 `ICOMM` および 南北方向の境界領域の幅 `JCOMM` はそれぞれ `ISTR-1`, `JSTR-1` で定義されている。

新たなスキーム等を導入する際に、あるグリッドの計算に対してより広い領域の情報が必要となる場合には、
`ISTR`, `JSTR` の値を大きくしなければならない。
同時にフラックスに対するマスキング (`AMFTX` など) で 0 でない値を設定するべき領域にも注意する必要がある。

## 9. 並列化モデルの状況に応じたチューニング

ノード間通信を伴う並列化におけるチューニングの基本は、いかに通信量と通信回数を少なくするかである。
同じ通信量ならば少ない回数で通信する方がよい。

このモデルでは外部モードの計算においてタイムスプリット法を用いており、スプリット中の毎ステップで通信が必要となる。
したがって、場合によっては `TMSTP` によって指定される内部モードのタイムステップを短くしてスプリット回数を減らす方が計算時間が短縮されることもある。
これは計算機のプロセッサの速度と通信速度の相対的関係によって決まるものであり、一般的なガイドラインを示すことはできない。
したがって、長時間の計算を行なう場合には、予備実験を十分に行なって最適な `TMSTP` と `NTSPLT` の配分を見つけることを強く勧める。

また、このパッケージではある程度の汎用性を持たせるために、場合によっては必要でない通信を行なっていたりする。
ここではプログラムの簡単な変更などによって明らかに計算時間の短縮が期待されるいくつかの例を紹介する。
いずれも実行時間にして数 % 程度の短縮にすぎないが、決して無視できる量ではない。
これにあてはまる場合には是非ともしたがって欲しい。

### 9.1 Turbulence closure scheme を使わない場合

この場合には `AMH`, `AHV`, `TAUX`, `TAUY` に関する通信は必要でない。
したがって、`aocea.F90` および `aprdc.F90` におけるそれらの変数の通信部分を削除する。

### 9.2 領域分割の個数があまり大きくない場合

領域を 2 や 4 程度の比較的少ない個数に分割する場合(実際にはこの程度で用いるのがほとんどであると思う)、
東西方向にのみ分割を行なう方がよい。すなわち、`JNODES = 1` とする。

モデルにおいて東西方向には周期境界条件が仮定されているため、その境界条件の取得のために、
たとえ東西方向に分割されていなくても東西方向には通信が発生するようにコーディングされている。
一方、南北方向には分割されていなければ通信は行なわれない。
したがって、南北方向に分割されていなければ 1 対 1 通信の回数が半分になると考えてよい。
なお、南北方向に分割をするのであれば、それが 2 分割であろうとも 4 分割であろうとも、通信の回数は変わらない。

南北方向に分割されていなければ 1 対 1 通信の回数が少なくて済むということは、分割の個数に関わらず常に成り立つ。
しかし、通信量という観点からすると、東西のみに分割を行なっていると分割数に関わらず個々のノードの通信量は一定であるが、
東西・南北両方向に分割を行なうと分割数を増やすほど個々のノードの通信量は減少する。
数十個以上のノードを使う、いわゆる massive parallel では東西・南北両方向に均等に分割する方がよいかもしれない。
南北方向のみに分割するのは避けるべきである、というのは確かであろう。

## 12. その他、注意点など

### 静水圧・海面高度と海氷

海氷の融解・生成に伴ってその場の海水 (液体としての体積) は増減する。
モデル変数の海面高度 `SH` は海水量を反映したものであるため、海氷とともに変動し、厚い海氷の下では顕著に低い高度を与える。
実際の状況では海氷が海水中に沈んでアイソスタシーが成り立つ。
したがって本来の意味での (ないし力学的な) 海面高度は、
モデル変数の `SH` に、その上にある海氷 (および雪) の分を加えたものである。
モデルにおける海面昇降に伴う水平圧力勾配の計算では、海氷の寄与分も正しく考慮されており、例えば海面重力波の表現が歪められることはない。

ただし、数値ノイズ除去のために入れてある `SH` の水平拡散は `SH` そのものに作用させているため、
海氷の厚さが水平方向に大きく変化する場所では、大きな `SH` 拡散を与えてしまう。
拡散によって `SH` が平滑化されても、上に乗っている海氷は平滑化されず、
海氷厚に基づく水平圧力勾配もそのまま残るので、拡散による平滑化を埋め合わせるような流れが駆動されることになる。
したがって、海氷厚が水平方向に大きく変化している場合、放っておいたらその下の `SH` の水平勾配が無くなっていくわけではなく、
海氷厚の水平変化と整合する状態が保たれる。

海氷の運動方程式の forcing term には海面勾配の項 (海面の「坂」を下る加速度) が含まれるが、
その海面高度が海氷厚に陽に依存する形で定式化されると、海氷厚の移流方程式と一緒になった時に海氷厚に重力波が表現されてしまう。
これはタイムステップ制約の原因となってしまうので、この項を無視 (`ipmmt.F90` で力学的海面高度に相当する変数 `HH` を強制的に 0 に) している。
高解像度で海氷の短周期変動を扱う場合には、これを無視しない方がよいかもしれない (`ipmmt.F90` では本来の `HH` の定義の仕方がコメントアウトして書いてある)。

### 年々変動する境界条件を与える場合

[5.4](#bound-time-interp-init) で述べたことそのままだが、重要なので繰り返しておく。境界条件ファイルに書かれた年とモデルで管理している時刻の年を一致させたい場合、
モデルの積分開始時刻よりも前の時刻を境界条件ファイルの先頭に用意しなければならない。

### 海氷モデル 2 カテゴリー (ないし少数カテゴリー) で動かす

単純に `NIC = 1` として、プログラム上は支障なく動作する。
しかし、マルチカテゴリーの定式化は、ridging の表現ないし力学的強度の計算において、本来そういうことを想定していない。
この場合、海氷力学的強度の計算を旧来の 2 カテゴリーの方法で行なうの方がより妥当である。それには
```fortran
&NMIDYN OPT_PICE=T &END
```
を指定する (詳細は前述)。

### 海氷熱力学によるタイムステップ制約

海氷の鉛直 1 次元熱伝導方程式に相当するものを陽解法で解いているため、それに起因するタイムステップへの制約が存在する。
これは、海氷厚の最低値が 10 cm の場合で 2 時間程度となる。
この値は海氷厚最低値の 2 乗に (おそらく) 比例するので、低解像度のモデルを加速して動かす場合などには、
海氷厚最低値を 30～50 cm 程度 (2 カテゴリーとしては、これくらいがよく用いられる/推奨される) とすることで、
この制約をあまり問題視せずに済むと思われる。
